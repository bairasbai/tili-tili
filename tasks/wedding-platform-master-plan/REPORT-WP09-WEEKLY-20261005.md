## Поведение и решения

На главной сохранена короткая карточка трёх ближайших реальных сроков. По отдельной кнопке раскрывается недельный обзор:

- незавершённые задачи с любым более ранним сроком — отдельная группа просроченных;
- сегодня–воскресенье включительно — задачи до конца текущей календарной недели;
- отсутствующий или невалидный срок — отдельная группа без срока, с разными объяснениями;
- задачи следующей недели и позже — отдельный счётчик и переход в существующий чек-лист;
- все строки обзора открывают существующий `/wedding/checklist`; никаких записей в API, новых разрешений или локальной копии задач нет.

Неделя — понедельник–воскресенье, точные границы и пояс видны. Дата «сегодня» берётся по серверному поясу свадьбы через существующий `useOfferDay`; отсутствие пояса использует его прежнее `Europe/Moscow`-умолчание. Невалидный пояс или недоступные метаданные не подменяются календарём устройства: показано отсутствие календаря. Расчёт границ — date-only UTC calendar arithmetic после определения локальной даты, без прибавления 24 часов через DST.

Часы работают только при раскрытом доступном обзоре; смена суток и возврат во вкладку используют прежний hook. При закрытии, потере актуального ответа или размонтировании таймер удаляется. При смене свадьбы ключ сбрасывает раскрытие.

## Дополнительная поправка к первому инкременту

`ready(q)` не включает `q.refreshing`. Поэтому первая версия PR #44 закрывала initial loading/error/403, но **не** окно фонового обновления. Утверждение его первоначального отчёта о любом reload было слишком широким. В этой поставке явный `!tq.refreshing` закрывает старые строки и пустые состояния карточки, а `!wq.refreshing` закрывает старый календарь. Home regression наблюдает первый DOM commit через layout effect до того, как `useApi` успевает стереть старые данные passive effect-ом.

## Карта экранов / дополнение R-MAP

Home → «Ближайшие дедлайны»: прежние три строки + раскрываемый «Задачи этой недели». Состояния: свернуто; актуальный обзор; календарь недоступен; обновление/отказ данных — без старых заголовков и счётчиков. Обзор содержит реальные даты, пояс, три группы и счётчик будущих задач. Формат RU/EN, существующие дизайн-токены, перенос длинных названий.

## Карта кнопок / дополнение R-BTN

«Показать / скрыть недельный обзор» → локальное раскрытие, aria-expanded/aria-controls, без сетевой записи. Каждая строка задачи и «Открыть весь чек-лист» → `/wedding/checklist`. Кнопки имеют type=button и не отправляют внешнюю форму.

Эти дополнения находятся в данном scoped report; большие корневые карты экранов/кнопок в этой поставке не переписаны.

## Проверки

Авторские проверки: календарные границы/воскресенье/год/високосный день/DST/невалидные даты/разбиение без потерь/неизменность источника/пояса; UI-группы и действия; обновление календаря/cleanup; RU→EN→RU; безопасный текст; смена владельца обзора; Home с реальным useApi и управляемыми API-ответами.

Словарный сторож расширен новым файлом; старые assertions не удалены и не ослаблены. Дополнительный тест проверяет сохранение всех прежних core-переводов. Базовые `Home.tsx`, `i18n.ts` и `dictionary.test.ts` сверены с Git blob до редактирования.

При создании этого документа новые Vitest/type/lint/build проверки ещё ожидают облачного CI на опубликованном коммите. Локальная transpilation не заменяет полный typecheck. Результаты GitHub Actions должны быть привязаны к actual checkout SHA/tree; pull_request workflow может проверять виртуальный merge-ref, а не literal feature SHA. Проверка равенства деревьев нужна отдельно.

Живой браузерный сценарий именно нового раскрываемого обзора, визуальная приёмка и физическое устройство пока не выполнены. Успех старых browser suites не подменяет эту приёмку. API, backend, миграции, существующие CI workflows, secrets и main не изменены.
