# Продуктовое ТЗ

Статус: целевые требования, а не описание уже выпущенного приложения. Источники и подтверждённые ограничения — [baseline.md](baseline.md). Реализация расширяет действующие продуктовые правила, документы и roadmap, перечисленные в [README](README.md).

## 1. Пользователи и результат

| Роль | Главная работа | Успешный исход |
|---|---|---|
| Пара | Решения, команда, бюджет, приглашения | Понятно, что делать дальше, за что платим и кто отвечает |
| Гость / представитель семьи | Ответ, маршрут, участие | Получил нужную информацию, указал каждого участника, не потерял изменения |
| Подрядчик | Продажа и исполнение заказа | Согласованные условия, актуальная программа, оплата и сдача результата |
| Сотрудник подрядчика | Свой участок работы | Видит только назначенные заказы и необходимые сведения |
| Координатор / организатор | Несколько свадеб, программа и исполнители | Может провести день по актуальной версии и передать полномочия |
| Помощник / родственник | Делегированные задачи | Видит конкретную ответственность без лишних частных данных |
| Поддержка / модератор | Обращения, споры, качество каталога | Разбирает ситуацию с причиной доступа и историей действий |
| Оператор сервиса | Доступность, тарифы, восстановление | Обслуживает продукт и подтверждает состояние внешних служб |

## 2. Истории и приоритеты

P1 — основной законченный сценарий; P2 — следующее расширение; P3 — развитие после пилота. Приоритет не отменяет порядок этапов и технические зависимости.

| История | Приоритет | Отдельно полезная поставка |
|---|---|---|
| US1 Подготовить личный план | P1 | Дата/формат/готовность → ближайшие задачи и ответственные |
| US2 Понять полную стоимость | P1 | Согласованная смета, доплаты, график и неопределённости |
| US3 Выбрать исполнителя | P1 | Кандидаты → предложения → сравнение → бронь |
| US4 Собрать покупки и вещи | P2 | Покупка/аренда → доставка → передача → возврат |
| US5 Пригласить людей | P1 | Семья и отдельные персоны → ответы → меню/места |
| US6 Провести мероприятия | P1 | Несколько событий, актуальное расписание и переезды |
| US7 Обеспечить логистику | P1 | Гости, места, транспорт, гостиницы и изменения |
| US8 Выполнить заказ | P1 | Календарь → бриф → команда → сдача результата |
| US9 Сохранить договорённости | P1 | Версии, согласование, документы, изменения условий |
| US10 Управлять днём свадьбы | P1 | Инструкции, план Б, доставка и подтверждения |
| US11 Завершить свадьбу | P2 | Расчёты, материалы, возвраты и архив |
| US12 Получить помощь | P2 | Приоритетная главная, безопасные предложения Тиля, поддержка |
| US13 Пользоваться платным сервисом | P1 перед платным запуском | Понятные права, оплата подписки, окончание доступа без потери данных |

## 3. Функциональные требования

### Подготовка и совместные решения — US1

- FR-001. Начальная анкета учитывает дату или её отсутствие, город/площадки, формат, ориентир бюджета, число гостей, самостоятельную подготовку/организатора и уже выполненные действия. Пропуск вопроса не создаёт выдуманного ответа.
- FR-002. Уже забронированный вне приложения подрядчик отображается как внешняя договорённость; пара может добавить условия и контакты либо вернуть категорию в поиск. Отметка не выдаётся за подтверждение подрядчика.
- FR-003. План предлагает применимые задачи из шаблонов 12/9/6/3/1 месяц, последней недели, дня свадьбы и завершения. Пара может исключить задачу с причиной. При коротком сроке подготовки показываются приоритеты, а не только список просрочек.
- FR-004. Задача имеет ответственного, срок, состояние и напоминание. Передача, выход участника, завершение и перенос срока не оставляют старые напоминания активными.
- FR-005. Зависимости объясняют следующий шаг: например, окончательное меню зависит от ответов гостей. Блокировка не должна запрещать осознанное ручное решение пары; обход фиксируется.
- FR-006. Экран «На этой неделе» показывает задачи, платежи, ожидаемые ответы, неподтверждённые условия и ответственных. Для каждого пункта есть переход к действию.
- FR-007. Пара может пометить решение как требующее согласования обоих партнёров; видны предложенный вариант, ответы и действующая версия. Обычные действия не становятся обязательным двойным согласованием.
- FR-008. Доступ родственника/помощника выдаётся на конкретные обязанности; финансовые данные доступны только при отдельном разрешении, если это допускает действующая матрица ролей.
- FR-009. Перенос даты показывает затронутые сроки, договорённости и мероприятия до подтверждения; неизвестная доступность исполнителей явно отмечается.

### Деньги — US2

- FR-010. Сводка разделяет плановую оценку, согласованные обязательства, отмеченные оплаты, остаток к оплате, возвраты и резерв. Один расход не попадает в итог дважды из покупки и сделки.
- FR-011. Для платежей доступны этапы, срок, сумма, частичные отметки и история исправлений. Одна попытка с повторным нажатием не создаёт двойную оплату.
- FR-012. Ручная отметка, приложенный документ и подтверждённая провайдером операция различаются словами. Загруженный чек не равен проверенной банковской транзакции.
- FR-013. Каждая составляющая цены имеет состояние: включено / отдельно / не требуется / не уточнено. Неуточнённые суммы исключаются из «известного итога» с заметным предупреждением, а не заменяются нулём.
- FR-014. Предложение поддерживает доставку, монтаж/демонтаж, пробковый сбор, сверхурочные, трансфер, печать, упаковку, аксессуары, расходники, репетиции, свет и продление аренды. Для расчётной доплаты видны единица, количество и ставка.
- FR-015. Изменение количества гостей, часов или состава работ показывает расчёт разницы. Цена согласованного договора не изменяется без отдельного принятия новых условий.
- FR-016. Лимиты категорий и резерв редактируются; показаны превышение, известные расходы и неопределённости. Вклад семьи учитывается отдельно от расходов; обещание денег не обозначается полученными средствами.

### Выбор исполнителя — US3

- FR-017. Пара ведёт кандидатов по категории, сравнивает выбранных исполнителей и конкретные пакеты; не подставляются другие кандидаты без выбора пользователя.
- FR-018. Сравнение включает часы, команду, состав услуги, результат, срок сдачи, дополнительные расходы, условия отмены/переноса и актуальность доступности. Отсутствующее условие показано как неизвестное.
- FR-019. Запросы и ответы приватны для разрешённых участников. Подрядчик не получает чужие цены, состав конкурентов и неуказанный парой бюджет.
- FR-020. Предложение имеет срок действия и связь с датой/мероприятием. Устаревшее, заменённое, отозванное или относящееся к прежней дате нельзя принять как актуальное.
- FR-021. Принятие фиксирует выбранные условия в брони и закрывает конкурирующие запросы без раскрытия победителя. Одновременное принятие двух предложений на одно место не создаёт две брони.
- FR-022. Замена текущего исполнителя заранее объясняет отмену и возможную потерю брони. Частично завершённая операция показывает реальное состояние и следующий шаг, а не ложный общий успех.

### Покупки, аренда, вещи — US4

- FR-023. Покупка содержит количество, единицу, оценку/согласованную стоимость, ответственного, продавца или ссылку, срок, мероприятие и связь с бюджетом.
- FR-024. Состояния покупки: нужно, заказано, получено, передано на площадку, завершено; предусмотрены отмена и возврат. История хранит кто и когда изменил состояние.
- FR-025. Аренда отдельно хранит залог, сроки получения/возврата, ответственное лицо, возврат залога и спорную сумму. Возвратный залог показывается как необходимое движение денег, не автоматически окончательный расход.
- FR-026. Вещи объединяются в наборы: утро невесты/жениха, церемония, площадка, экстренный набор. Видно, у кого вещь и кто доставляет. Возможный дубль покупки предлагается проверить, но не удаляется автоматически.

### Гости — US5

- FR-027. Семейное приглашение объединяет отдельных персон; для каждой независимы имя/временное обозначение, участие, питание, место, транспорт и проживание. Представитель отвечает только за разрешённую семью.
- FR-028. Участие подтверждается отдельно на каждом мероприятии. Мест за столом, порций и мест в транспорте считается по персонам, а не по количеству приглашений.
- FR-029. Для гостя учитываются питание, аллергии, детские потребности и потребности доступности; свободные чувствительные заметки видны только тем, кому нужны для организации.
- FR-030. Приглашение содержит персональный состав мероприятий, сроки ответа, адреса, дресс-код и контакт координатора. Ссылка не раскрывает полный список гостей, бюджет и чужие ответы.
- FR-031. До установленного дедлайна гость редактирует ответ; после — отправляет запрос организатору. Пара может исправить ответ с указанием источника «внесено организатором».
- FR-032. Импорт показывает предпросмотр, возможные дубли и ошибки строк; повторный импорт не создаёт молча вторые записи. Печатная/передаваемая информация доступна для гостей без приложения.
- FR-033. Рассадка учитывает вместимость и отдельные персоны; конфликт или нерассаженный подтвердивший участие человек показан явно. Перенос одного гостя не стирает чужую правку.
- FR-034. Гость может выбрать/забронировать подарок, отменить бронь по правилам и загрузить разрешённые фотографии. Пара управляет видимостью альбома и удалением материалов.

### Мероприятия и расписание — US6

- FR-035. Свадьба объединяет выбранные парой мероприятия: регистрация, никах, церемония, банкет, второй день и произвольные события. Каждое имеет свои дату, место, часовой пояс, программу и приглашённых.
- FR-036. У блока программы сохраняется идентичность при редактировании. Видны действующая версия, автор и время изменения; старое сохранение не уничтожает чужую более новую версию.
- FR-037. Блок имеет длительность, зависимости, участников, ответственного, место и признак фиксированного времени. Переезды и буферы учитываются явно, автоматический расчёт времени маршрута не обещается без источника.
- FR-038. Изменение программы показывает затронутые блоки, исполнителей и перемещения. Подрядчик подтверждает ознакомление с конкретной версией; редактирование создаёт новое ожидание подтверждения.
- FR-039. Сдвиг применяется к выбранному дню/мероприятию и не сдвигает молча второй день, прошедшие или фиксированные блоки. Неразрешимый конфликт требует решения координатора.
- FR-040. Последний сохранённый план дня доступен без сети с временем снимка. Офлайн-копия явно отличается от актуальной серверной версии; критическое действие без подтверждения сервера не отображается выполненным.

### Транспорт и проживание — US7

- FR-041. Трансфер содержит маршрут, остановки, время, перевозчика/контакт, вместимость и список отдельных пассажиров. Семья может ехать разными рейсами; переполнение запрещено.
- FR-042. Гость может отказаться от своего места или запросить изменение после дедлайна. Срочная замена транспорта показывает контакт и инструкцию; приложение не обещает заказ такси, если интеграции заказа нет.
- FR-043. Проживание учитывает отдельные персоны, номера/вместимость, даты заезда/выезда, ответственного и источник подтверждения. Размещение в списке не выдаётся за оплаченную бронь гостиницы.
- FR-044. Гость получает вход на площадку, парковку, доступный маршрут и точку посадки. Изменение точки приводит к адресному уведомлению затронутых людей.

### Работа подрядчика — US8

- FR-045. Календарь различает свободно, предварительная бронь, занято и неизвестно; видны последнее обновление и источник. Необновлённый календарь не гарантирует доступность.
- FR-046. Внешние заказы и импорт календаря учитывают занятость, не раскрывая пары и детали чужого заказа. Импорт не может освободить подтверждённую бронь приложения.
- FR-047. Компания назначает сотрудников и ресурсы на интервалы с учётом переездов/монтажа. Один человек или комплект не назначается в несовместимые заказы.
- FR-048. Карточка заказа объединяет обращение, предложение, договорённости, бриф, расписание, документы, платежи, задачи и следующий шаг; существующие состояния сделки сохраняют смысл.
- FR-049. Бриф зависит от профессии: фото/видео — люди, моменты, референсы, ограничения публикации и результаты; ведущий — имена, программа и запретные темы; площадка/декор — питание, монтаж и техника. Пара подтверждает действующую версию.
- FR-050. Сдача содержит согласованные результаты, сроки, ссылки/файлы, комментарии и этапы правок. Просмотр ссылки и приёмка результата различаются.
- FR-051. Аналитика использует сопоставимые периоды и объясняет определения обращения/заказа/выручки. Просмотры не считаются клиентами; неизвестные данные не становятся нулём.
- FR-052. Организатор ведёт несколько свадеб и выдаёт доступ сотрудникам по свадьбе. Увольнение/выход снимает доступ и требует переназначения задач, не удаляя историю.

### Документы и согласования — US9

- FR-053. Версии договора и приложения к нему сохраняются; видно, какая редакция предложена и согласована каждой стороной. Новая редакция не наследует старое согласие.
- FR-054. Подписанный вне сервиса файл можно прикрепить с автором и датой. Загрузка файла и нажатие «согласовано» не называются электронной подписью или юридической проверкой.
- FR-055. Перенос, отмена, дополнительная работа и изменение цены оформляются отдельным изменением условий с последствиями для расписания и платежей. История первоначальной договорённости остаётся доступной разрешённым сторонам.
- FR-056. Удаление аккаунта, архив и срок хранения не уничтожают данные произвольно: пользователь заранее видит последствия; сохранение/обезличивание следует утверждённой политике и применимым требованиям.

### День свадьбы и уведомления — US10

- FR-057. Координатор видит ближайшие блоки, контакты, время приезда, готовность исполнителей и незакрытые задачи. Финансы скрыты без разрешения.
- FR-058. План Б содержит причину, условия включения, конкретные действия, ответственных, резервную площадку/точку и контакты. Нельзя объявить новый адрес, если он не указан.
- FR-059. Перед включением плана Б показаны изменения и получатели. Повторное нажатие не создаёт повторную операцию или лавину одинаковых уведомлений.
- FR-060. Уведомление различает затронутых, поставленных в очередь, переданных провайдеру, доставленных по подтверждению и прочитанных/подтверждённых пользователем. Отсутствующий статус не угадывается.
- FR-061. Недоступный канал показывает причину и альтернативу: готовый текст, ссылка или звонок. Автоматическое переключение на платный канал ограничивается настроенным лимитом.
- FR-062. Чувствительные сведения не попадают в общую рассылку, экран блокировки и чужую гостевую ссылку. Обычные сообщения соблюдают тихие часы; срочное исключение связано с конкретным событием.

### Помощь, завершение, поддержка — US11/US12

- FR-063. Главная ранжирует действия по срокам и последствиям и объясняет причину приоритета; пара может отметить уже решённое и скрыть неприменимое.
- FR-064. Тиль предлагает действия на основе доступных ему данных с предпросмотром: что изменится, почему и кого затронет. Запись, отправка, отмена или изменение денег требуют явного подтверждения пользователя.
- FR-065. Тиль не раскрывает скрытый бюджет и чужие предложения, не исполняет команды из документов/переписки и не выдумывает доступность или цены. При отсутствии данных сообщает об этом.
- FR-066. После последнего мероприятия открывается план завершения: платежи, возвраты, материалы, правки и отзывы. При двухдневной свадьбе этот режим не включается посреди праздника.
- FR-067. Доступны благодарности гостям, разрешённый общий альбом и выгрузка данных; отправка выполняется после выбора адресатов и подтверждения текста.
- FR-068. Обращение в поддержку имеет тему, состояние, ответственного и историю. Чтение частных материалов сотрудником ограничено назначением и журналируется; доступ к переписке не появляется автоматически.
- FR-069. Модерация различает подтверждение документов, качество работы и отзыв клиента. Жалоба/оспаривание имеет решение и причину; подрядчик может исправить отклонённую анкету.

### Тарифы и самостоятельность пользователя — US13

- FR-070. Тарифные права сервиса отделены от денег по сделкам подрядчиков. Цена, период, лимиты, условия окончания и возврата показаны до оплаты.
- FR-071. Подтверждение оплаты подписки приходит из проверенного источника; повтор уведомления провайдера не начисляет права дважды. Возврат и отмена меняют права по объявленным правилам.
- FR-072. Окончание подписки не удаляет свадьбу, договоры и подтверждения оплат. Режим чтения/экспорта и ограничения редактирования объясняются заранее; экстренная информация дня свадьбы не блокируется неожиданно.
- FR-073. Гостевой ответ, необходимая информация приглашения и отказ от участия доступны без платной подписки гостя. Платная функция не имитирует успех до получения прав.

## 5. Критерии приёмки

Все сценарии ниже — обязательные наблюдаемые исходы, а не текущие результаты тестов. ID SC используются в плане и задачах.

- SC-001 (FR-001–009): новая пара без даты и пара со свадьбой через месяц получают применимый план; пропуски, выполненные брони, делегирование и перенос даты сохраняются после повторного входа.
- SC-002 (FR-010–012,016): ручная покупка и связанная сделка учитываются один раз; частичная оплата, исправление и возврат дают объяснимый остаток; повтор запроса не удваивает сумму.
- SC-003 (FR-013–015): сравнение явно показывает неизвестные доплаты; изменение числа гостей меняет только расчётный сценарий до принятия новой сметы.
- SC-004 (FR-017–022): две сессии пары и кабинет подрядчика проходят запрос → ответ → сравнение → принятие; истёкший ответ, чужая роль и двойное принятие отвергаются без лишней брони.
- SC-005 (FR-023–026): покупка проходит все состояния, аренда возвращается с залогом, вещь передаётся другому ответственному; бюджет и история согласованы.
- SC-006 (FR-027–034): семья из трёх персон независимо отвечает за разные мероприятия, имеет разные блюда и рейсы; перенос и отказ одной персоны меняют только её размещение и соответствующие итоги.
- SC-007 (FR-032): повтор импорта после обрыва не создаёт дубли; отказ одной строки не скрывает успешность других и не оставляет непонятное состояние.
- SC-008 (FR-035–040): редактирование сохраняет идентичность блока; устаревшее сохранение получает конфликт; сдвиг дня 1 не меняет день 2 и фиксированные события.
- SC-009 (FR-041–044): два одновременных запроса последнего места дают одну успешную запись; отказ освобождает место; ошибочный рейс и чужая семья недоступны.
- SC-010 (FR-045–047): внешний календарь не освобождает действующую бронь; ресурс нельзя назначить на пересечение, неизвестная актуальность видна.
- SC-011 (FR-048–052): подрядчик проходит бриф → назначение сотрудника → сдачу → правки → приёмку; у удалённого из команды сотрудника доступ прекращается.
- SC-012 (FR-053–056): обе стороны видят согласованную версию; новая редакция требует нового согласования; удаление/архив следуют политике без потери обязательной истории.
- SC-013 (FR-057–062): план Б указывает реальный адрес, действия и получателей; недоступный канал не показывает «доставлено»; повтор операции не дублирует сообщения.
- SC-014 (FR-063–065): Тиль предлагает допустимое действие, показывает изменения и не выполняет их без подтверждения; чужой контекст и инструкция из вложения не меняют права.
- SC-015 (FR-066–069): после последнего мероприятия доступны сдача, возвраты, отзывы и поддержка; общий альбом не раскрывает закрытые материалы.
- SC-016 (FR-070–073): повтор webhook не удваивает период/права, поддельный webhook не выдаёт доступ; окончание тарифа сохраняет объявленный режим чтения и гостевую информацию.
- SC-017 (все FR): каждая роль проходит разрешённый сценарий и получает понятный отказ в чужом; нет межсвадебной утечки в поиске, выгрузке, файлах, уведомлениях и действиях Тиля.
- SC-018 (все FR): пустое состояние, загрузка, потеря сети, конфликт версии, отказ доступа и недоступная интеграция не выглядят успешным сохранением или нулевыми данными.

## 6. Предлагаемые умолчания и границы

- Сроки подготовки — редактируемые рекомендации; религиозные/культурные мероприятия выбирает пара.
- Уведомление не гарантирует прочтение; действие координатора и сообщение гостю — разные результаты.
- Общение и документы, нужные для выполнения заказа, не открывают подрядчику весь бюджет или всю базу гостей.
- Деньги между парой и подрядчиком сначала учитываются существующим способом. Эскроу, кредитование, приём денег за подрядчика и налоговый учёт не входят без отдельного проекта.
- Подписание квалифицированной электронной подписью, автоматическое бронирование гостиниц/такси, государственные заявления и универсальный интернет-магазин не обещаются этим ТЗ.
- Прогноз погоды — опциональная интеграция с временем обновления; без провайдера остаются ручная проверка и план Б.
- RU/EN наследуются из проекта. Новые языки добавляются отдельным решением с проверкой переводов; культурные шаблоны не требуют автоматического включения языка.
- Точные тарифы, платные каналы и политика хранения получают решение перед соответствующим выпуском; подготовка ТЗ и остальных независимых этапов продолжается без этих значений.
