База: `4c41e4abceba1750fa3cc388455397c93782fe7f`, PR45. Не сливать и не выкладывать.

## План до реализации

- [x] Добавить необязательную read-only проверку условий из существующих slots, order/catalog и order/terms.
- [x] Проверять свадьбу/роль до чтения условий, ограничить параллельность, остановить очередь при уходе/смене сессии.
- [x] Отличать отсутствие публикации, ожидание каждой стороны, актуальную согласованную и устаревшую редакцию; ошибки не считать подтверждением.
- [x] Добавить чистые и React/HTTP регрессии, проверить RU/EN, типы, полный frontend, lint/build и браузер.
- [ ] Обновить карты, журнал, handoff; опубликовать отдельный коммит без merge. Полный CI и backend не заменять frontend-проверкой.

Сроки подтверждения не передаются API и не выдумываются. Проверка охватывает активные сделки в текущих слотах, не весь исторический реестр заказов и не отметки prebooked без сделки. Денежные поля и readToken не сохраняются в проекции. Принимать/публиковать условия можно только в существующей карточке заказа после её собственных проверок.

## Фактический результат текущего среза

Добавлен раздел `WeeklyOrderTerms`, чистая проверка метаданных и ограниченный GET-сборщик. До кнопки запросов условий нет. Для каждой сделки catalog подтверждает ту же свадьбу и роль пары перед GET terms. Персональные ответы не подменяют ответ стороны. Только совпадение серверного указателя согласования и двух подтверждений с тем же digest даёт актуальное согласование; stale/unavailable/invalid остаются отдельными состояниями. Метаданные сбрасываются на смене свадьбы/сессии; queue прекращает новые запросы после ухода. Ошибки отдельных заказов не становятся согласием и не скрывают остальные результаты. Полные 403 не предлагают ложного повтора. Читать можно старый согласованный вариант, но его ответы не переносятся на новую редакцию.

- 55 новых тестов: 34 чистых + 21 React/HTTP. Управляемая сеть, не PostgreSQL.
- Регрессия интеграции с настоящим WeeklyAgenda на старой версии файла: 1 FAIL; после подключения — 1 PASS. Это намеренный `-t` запуск одного случая, остальные 20 не выбирались. Полный новый набор выполнен отдельно без пропусков.
- Полный frontend: **2321/2321 PASS, 120 файлов, 0 failed, 0 pending**. 2266 базовых + 55 новых = 2321.
- Полная TypeScript-проверка frontend, полный ESLint и production build: exit 0.
- Локальный Chromium: **BLOCKED** до загрузки страницы, `net::ERR_BLOCKED_BY_ADMINISTRATOR`. Ни один новый браузерный сценарий/снимок не засчитывается. Browser policy не менялась и не обходилась; временные файлы и Vite-сервер удалены/остановлены.
- Backend, настоящая PostgreSQL, физические устройства и новый exact-head GitHub CI не подтверждены этими проверками. Исходные падения/отмены CI и запрет записи прежнего weekly browser fixture не исправлялись этой фичей.

Карты экранов/кнопок, JOURNAL, todo и handoff обновлены. Граница поставки: наблюдение за условиями активных сделок в текущих слотах, не весь исторический реестр. Отметки prebooked без сделки и закрытые сделки не представлены как проверенные заказы. Сроки подтверждения отсутствуют в API и не угадываются. Никаких публикаций/принятий, оплаты, миграций, новых ролей или доступа к чужой свадьбе код не добавляет. Это часть FR-006/WP09, не полное закрытие WP09 или всего проекта.

Независимый второй агент не привлекался: исходники сверены реализующим ассистентом с существующим серверным project/terms и контрактом. Не сливать в main; пользователь выполняет merge самостоятельно после оставшейся приёмки.
