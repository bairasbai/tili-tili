## Правила использования

- Перед кодом обновить снимок веток и CI: baseline — исторический срез, не вечное состояние.
- Различать: существует в main / существует в отдельной ветке / начато / предлагается / требует внешней настройки.
- Не переписывать архитектуру и не строить повторно существующие подсистемы.
- Поставлять каждый этап законченным сценарием: данные, права, API, экран, ошибки, тесты, карты, документация.
- Не отмечать этап готовым по числу коммитов, зелёному фронтенду или тестам с пропущенной БД.
- Разрешена публикация этого плана отдельным коммитом. Реализация, слияние в main и production deployment в это поручение не входят.
- Цены тарифов, юридические обещания и оплачиваемые внешние услуги этим документом не утверждаются.

## Ожидаемые результаты программы

- Пара видит ближайшие решения, реальные обязательства, платежи и неопределённые расходы.
- Каждая персона учтена один раз в приглашениях, меню, рассадке и логистике.
- Подрядчик ведёт заказ от обращения до сдачи результата с сохранением договорённостей.
- Координатор управляет конкретными действиями и видит подтверждения участников.
- Гость получает персональную информацию и может ответить без обязательной установки приложения.
- Оператор может доказать доставку в пределах возможностей канала, восстановить данные и разобрать спор по журналу.
