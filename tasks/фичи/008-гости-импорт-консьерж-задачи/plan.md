## Фазы

### Фаза 1 — контракт (~20 мин)
`POST /weddings/{weddingId}/guests/import`: тело `{ guests: [{ name (2…120), phone? (≤32), plusOne? (bool), group? (≤60) }] }`,
`minItems 1`, `maxItems 300`; 201 `{ created: Guest[], skipped: [{ index, name, reason: duplicate|invalid }] }`; 403/404/422.
Описание: разбор — на клиенте, дедупликация — на сервере; повтор того же списка добавляет ноль.

### Фаза 2 — бэкенд (~1,5 часа)
`guests.ts`: обработчик рядом с `POST …/guests` (те же права); транзакция: `select id from weddings where id = $1 for update`
(два одновременных импорта не дадут дублей), существующие гости `lower(regexp_replace(name,'\s+',' ','g'))` и `phone`;
нормализация телефона (`8XXXXXXXXXX`/`7…`/`+7…` → `+7XXXXXXXXXX`; иначе `invalid`); вставка `insert … select from unnest`
или циклом в транзакции (≤300 строк — цикл допустим); ответ созданных через общий `toGuest(r, asCouple)`.
Тест `audit37`: три строки → три гостя; повтор → 0 добавлено, 3 `duplicate`; телефон `12345` → `invalid`, остальные добавлены;
301 строка → 422; помощник может импортировать (права как у `POST`); два параллельных импорта одного списка → гостей ровно N.

### Фаза 3 — фронт (~3 часа)
1. `lib/guestsImport.ts`: `parseGuestList(text): ParsedRow[]` (имя, телефон, plusOne, группа? нет; ошибки строк) — чистый модуль
   с юнит-тестами (регистры, «+1», телефоны `8…`/`+7…`, пустые строки, разделители).
2. `Guests`: кнопка «Добавить списком» рядом с «Пригласить» → панель: textarea, предпросмотр (таблица строк с пометками
   «уже в списке» — по текущему списку `q.data`, «телефон не распознан»), «Добавить N гостей» (N — валидные) → `importGuests` →
   `q.reload()` → итог «Добавлено N · пропущено M» из ответа; ошибка — текст сервера; ноль ≠ неизвестно.
3. `VendorList`: при `ready(list)` и пустом списке — «Оставить заявку консьержу» → форма (бюджет ₽, комментарий) → `POST` →
   «Заявка принята — свяжемся в течение суток» / 409 словами сервера; без входа — кнопки нет (`isAuthorized()`).
4. Чек-лист: тап по строке — раскрытие (срок/период), «Переименовать» inline → `PATCH`, «Удалить» → подтверждение → `DELETE`;
   галочка выполнения — как была.
5. Словарь, `audit35.test.tsx`, карты (`feature-008`).

### Фаза 4 — записи (~30 мин)
План §20.1 (№29 → «да», №18 → «да», №12 → «внутри»), JOURNAL, todo, handoff, ERRORS при находках.

## Решения (по поручению владельца)

| № | вопрос | решение |
|---|---|---|
| Р1 | Формат импорта | вставка текста, строка = гость; файлы — нет (хранилища нет) |
| Р2 | Дубликаты | пропускаются (не обновляются), причина в ответе |
| Р3 | Где консьерж | экран категории при пустой выдаче |
| Р4 | Деталь задачи | раскрываемая строка без отдельного маршрута; заметок нет (миграция) |

## Открытые технические вопросы

- `group` в импорте: не разбирается из текста (нет надёжного признака) — принимается полем на будущее, экран не заполняет.
- Нормализация имён для дедупликации — нижний регистр и схлопывание пробелов; «Аня» и «Анна» — разные гости (намеренно).
