# Спека: Импорт гостей списком, заявка консьержу, деталь задачи

**Папка:** tasks/фичи/008-гости-импорт-консьерж-задачи · **Заведена:** 2026-09-12 · **Статус:** в работе — выбор и решения
по поручению владельца («дальше — выбор ваш», 2026-09-12). Экраны Плана §20.1: 29 «Импорт гостей», 18 «Консьерж-заявка
(пустая выдача)», 12 «Деталь задачи».

## Зачем

Три экрана MVP без маршрута, которые не требуют внешних служб (в отличие от фото гостя — хранилище №3, и входа по email —
отправитель писем №13). **Импорт гостей:** сейчас гости заводятся только по одному — на свадьбе 80–150 человек это час
ручной работы, а список у пары уже есть (заметки, таблица, мессенджер). **Консьерж-заявка:** путь `POST /catalog/concierge`
реализован (План §18.12 — «пока в городе меньше 50 анкет, поиск честно предлагает подбор вручную за 24 часа»), но экрана
и вызова нет — пустая выдача предлагает только спросить Тиля. **Деталь задачи:** строка чек-листа не раскрывается — тап
отмечает выполнение; переименовать или удалить задачу нельзя, хотя `PATCH`/`DELETE` в контракте есть.

## Границы

**Входит:** вставка списка гостей текстом (строка = гость: имя, необязательно телефон и «+1»), разбор на клиенте с
предпросмотром, один запрос `POST /weddings/{weddingId}/guests/import` (контракт, новый), дедупликация по имени и телефону
внутри свадьбы, потолок 300 строк за раз; заявка консьержу с экрана категории при пустой выдаче (форма: бюджет, комментарий),
409 «уже в работе» словами сервера; раскрываемая строка задачи: срок, период, «Переименовать», «Удалить», выполнение.

**Не входит:** загрузка файлов (CSV/XLSX как файл — читается вставкой текста; файловое хранилище — блокер №3); импорт
телефонов в формате не `+7…` (нормализуется только российский номер); заметки к задаче (нет колонки — миграция).

## Истории

### US1 — Пара заводит гостей списком (P1) 🎯 MVP
**Как** пара, **я хочу** вставить список из заметок и получить гостей одним нажатием, **чтобы** не вбивать 100 имён руками.
1. Дано: вставлено «Анна Петрова, +79170001111, +1 / Марк / Ольга и Сергей» — тогда предпросмотр показывает три строки
   (имя, телефон, «с +1»), кнопка «Добавить 3 гостей» → в списке трое, пустых и повторов нет.
2. Дано: в списке уже есть «Марк» — тогда предпросмотр помечает строку «уже в списке», она не добавляется, ответ сервера
   говорит «добавлено 2, пропущено 1».
3. Дано: строка без имени или телефон не по формату — тогда строка помечена ошибкой и не уходит; остальные добавляются.

### US2 — Пара оставляет заявку консьержу (P2)
**Как** пара, **я хочу** при пустой выдаче в категории оставить заявку с бюджетом и пожеланием, **чтобы** подбор сделали за
меня. Дано: заявка уже в работе — 409 словами сервера; успех — «Заявка принята, свяжемся в течение суток» (обещание есть в
контракте и Плане §18.12 — на экране ничего сверх него).

### US3 — Пара правит задачу (P3)
**Как** пара, **я хочу** раскрыть задачу, увидеть срок и период, переименовать или удалить её, **чтобы** чек-лист был моим,
а не шаблонным.

## Требования

- **FR-001** Контракт: `POST /weddings/{weddingId}/guests/import` — тело `{ guests: [{ name, phone?, plusOne?, group? }] }`
  (1…300), ответ 201 `{ created: Guest[], skipped: [{ index, name, reason: 'duplicate'|'invalid' }] }`; 422 на пустое тело/
  >300; права — как у `POST …/guests` (вся команда).
- **FR-002** Сервер: одна транзакция; дубликат — совпадение имени без учёта регистра и пробелов ИЛИ совпадение телефона
  с уже существующим гостем свадьбы или с другой строкой того же запроса; телефон нормализуется к `+7XXXXXXXXXX`,
  не нормализуемый — `invalid`; имя ≥ 2 символов.
- **FR-003** Экран гостей: кнопка «Добавить списком» → поле для вставки → разбор на клиенте (разделители: перенос строки;
  внутри строки — запятая/точка с запятой/таб; «+1», «с +1», «+ 1» → `plusOne`; `+7…`/`8…` 11 цифр → телефон) →
  предпросмотр с пометками → «Добавить N гостей» → один запрос → список перечитан; итог словами сервера.
- **FR-004** Категория с пустой выдачей (`ready` и 0 анкет, без фильтров или с ними): кнопка «Оставить заявку консьержу» →
  форма (бюджет — целые рубли, комментарий) → `POST /catalog/concierge` → «Заявка принята — свяжемся в течение суток»;
  409 `concierge_pending` — текст сервера; без входа — кнопки нет.
- **FR-005** Задача в чек-листе раскрывается: срок (`due`) и период, «Переименовать» (inline, `PATCH title`), «Удалить»
  (подтверждение, `DELETE`), выполнение — как было; шаблонные и свои — одинаково (сервер уже позволяет).
- **FR-006** Регрессии красные без фикса; карты и словарь той же итерацией; `audit14` согласен с контрактом.

## Критерии успеха

- **SC-001** 100 строк заводятся одним запросом за < 2 с, повторный импорт того же текста добавляет 0.
- **SC-002** Ни одна строка с ошибкой не блокирует остальные; итог совпадает с числом строк в списке.
- **SC-003** Полные наборы зелёные; `init.sh` exit 0.

## Допущения

- **A1** Разбор текста — на клиенте (предпросмотр без запроса), сервер принимает структуру и сам проверяет и дедуплицирует.
- **A2** Формат телефона — российский; иное «invalid» с подсказкой.
- **A3** Консьерж — только для вошедшей пары (путь требует токен).
