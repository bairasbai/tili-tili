# 017 — ответственные и сроки задач

Дата: 2026-09-26. Рабочая ветка: `feature/product-improvements-stage1-tasks`.
`main` и production не меняются; PR остаётся draft.

## Объём этой поставки (017-A)

- Ответственный из живой команды свадьбы: couple/helper/coordinator; назначение и явное снятие.
- «Мои задачи», «Без ответственного», «Все задачи», фильтры периода без потери задач другого периода.
- Точная календарная дата; fixed/relative; осознанное снятие срока.
- Создание и редактирование через UI → существующий API → PostgreSQL → повторное чтение.
- Миграция жизненного цикла назначения, генерация контракта, тесты прав/гонок/переноса.

В исходной поставке 017-A персональных напоминаний нет. Расширение 017-B описано ниже. Общий существующий дайджест не подменяет персональный планировщик.

## Инварианты

1. Задача относится к одной свадьбе. Assignee не открывает бюджет, документы или контакты.
2. Ответственный — живой участник этой свадьбы с организационной ролью. Vendor и посторонний отклоняются.
3. Удаление участника, мягкое удаление аккаунта и смена роли на недопустимую снимают назначение, но не удаляют задачу.
4. Проверка назначения и запись в одной транзакции: свадьба → пользователи → задача. Повторно проверяются живой автор и членство.
5. Срок без явного значения и режима при создании — relative, по существующему шаблону периода.
6. Явная дата или null без режима — fixed. Null означает намеренное отсутствие срока; перенос не восстанавливает его.
7. Relative с точной датой требует известной даты свадьбы. Relative без due восстанавливает расчёт из периода; fixed без due сохраняет текущую дату.
8. При переносе сохраняется существующее правило смещения relative на разницу дней. Fixed не меняется. Операции переноса остаются транзакционными.
9. Старые PATCH done/title и запрет удаления системной задачи сохраняются. Планирование planb-задач отвергается; галочки planb работают.
10. Неизвестный профиль/команда не трактуется как отсутствие назначений. При недоступной команде правка срока не отправляет assigneeId и не стирает старое назначение.
11. Во время записи и повторного чтения изменять прежнюю копию нельзя. Отказ сервера сохраняет черновик. Создание требует непустого названия.
12. Денежные расчёты, роли, гости и тайминг не перепроектируются этой поставкой.

## 017-B — уведомления назначения и одно настраиваемое напоминание

- Назначение другому живому участнику создаёт новость только ему, в транзакции записи задачи. Назначение себе и повтор тому же человеку не создают новость.
- У задачи один план: выключено (`reminderDaysBefore=null`) либо 0–30 дней до срока и местное время `reminderTime` в HH:mm. По умолчанию выключено; новое включение в UI предлагает один день и 09:00. Ноль означает день срока.
- Для включения нужны ответственный и срок. Снятие любого из них выключает план. Явное выключение не удаляет назначение или саму задачу.
- Пояс: профиль ответственного, затем свадьба, затем Москва; некорректный пояс безопасно приводится к Москве. Плановое время вычисляется сервером, не телефоном. После постановки в очередь повторно учитываются действующие тихие часы.
- `task-reminders` запускается штатным BullMQ раз в минуту. Два воркера сериализуются; отметка версии и уведомление сохраняются атомарно. Ошибка откатывает только неуспешную задачу, затем допускает повтор.
- Срок, исполнитель, выполнение и параметры напоминания изменяют версию. Старые сообщения исключаются из inbox и push; переименование обновляет текст, но не создаёт новое событие.
- Перед каждым обращением к push-провайдеру проверяются актуальная версия, членство, живой аккаунт, настройки и срок действия. Уже переданный провайдеру push отозвать нельзя. Используется прежняя at-most-once попытка транспорта, не обещание гарантированной доставки на устройство.
- Напоминание актуально не дольше 24 часов от планового времени и не после конца дня дедлайна. Назначение — 24 часа. После простоя старые напоминания не рассылаются залпом. Глобальное отключение task-уведомлений подавляет текущую попытку; включение позже не воспроизводит старые события.
- Тихие часы и общий дневной лимит сохраняются даже в день свадьбы. Отмена уже отправленного/заявленного push не возвращает потраченный лимит. Отменённые записи скрыты, удаляются уборкой через 90 дней.
- Ссылка новости содержит UUID задачи и свадьбы и раскрывает нужную задачу независимо от периода или активной свадьбы. Проверки доступа выполняются сервером; произвольные внешние ссылки не принимаются.
- UI сохраняет параметры вместе с остальной задачей, без запроса на каждый ввод; пустое время не подменяется незаметным умолчанием. RU/EN-строки синхронизированы.

Контракт **0.43.0**, миграция **1761200000000_task_reminders**. Очередь требует настроенного Redis и запущенного серверного воркера; внешний Web Push требует VAPID и подписки. Inbox не требует внешнего push-провайдера. Production-ключи этим этапом не меняются.

Повторяющиеся ежедневные напоминания о просрочке, несколько напоминаний на одну задачу, комментарии/зависимости и новые статусы задач не входят в 017-B. Это не завершение всей первоначальной продуктовой подборки.
