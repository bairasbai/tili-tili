# 017 — ответственные и сроки задач

Дата: 2026-09-26. Рабочая ветка: `feature/product-improvements-stage1-tasks`.
`main` и production не меняются; PR остаётся draft.

## Объём этой поставки (017-A)

- Ответственный из живой команды свадьбы: couple/helper/coordinator; назначение и явное снятие.
- «Мои задачи», «Без ответственного», «Все задачи», фильтры периода без потери задач другого периода.
- Точная календарная дата; fixed/relative; осознанное снятие срока.
- Создание и редактирование через UI → существующий API → PostgreSQL → повторное чтение.
- Миграция жизненного цикла назначения, генерация контракта, тесты прав/гонок/переноса.

Отдельный следующий шаг 017-B: персональные настраиваемые напоминания и уведомления при назначении. В этой поставке их нет. Общий существующий дайджест не выдаётся за персональный планировщик напоминаний.

## Инварианты

1. Задача относится к одной свадьбе. Assignee не открывает бюджет, документы или контакты.
2. Ответственный — живой участник этой свадьбы с организационной ролью. Vendor и посторонний отклоняются.
3. Удаление участника, мягкое удаление аккаунта и смена роли на недопустимую снимают назначение, но не удаляют задачу.
4. Проверка назначения и запись в одной транзакции: свадьба → пользователи → задача. Повторно проверяются живой автор и членство.
5. Срок без явного значения и режима при создании — relative, по существующему шаблону периода.
6. Явная дата или null без режима — fixed. Null означает намеренное отсутствие срока; перенос не восстанавливает его.
7. Relative с точной датой требует известной даты свадьбы. Relative без due восстанавливает расчёт из периода; fixed без due сохраняет текущую дату.
8. При переносе сохраняется существующее правило смещения relative на разницу дней. Fixed не меняется. Операции переноса остаются транзакционными.
9. Старые PATCH done/title и запрет удаления системной задачи сохраняются. Планирование planb-задач отвергается; галочки planb работают.
10. Неизвестный профиль/команда не трактуется как отсутствие назначений. При недоступной команде правка срока не отправляет assigneeId и не стирает старое назначение.
11. Во время записи и повторного чтения изменять прежнюю копию нельзя. Отказ сервера сохраняет черновик. Создание требует непустого названия.
12. Денежные расчёты, роли, гости и тайминг не перепроектируются этой поставкой.
