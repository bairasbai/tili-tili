## Исправленные причины падений стенда

1. Повреждённый shell-блок в прежней диагностической правке workflow. Исправленный YAML, каждый shell-блок и встроенный Python проверены до публикации.
2. Backend-suite оставлял записи OTP в общей тестовой БД: локально воспроизведены 1356 записей за час при лимите 500. Из-за этого fixture не создавал пользователей и файл сессий; FileNotFoundError был следствием, а не причиной. Браузеру выделена новая одноразовая БД; лимит авторизации не повышен, счётчики общего прогона не очищаются.
3. Браузерный fixture намеренно запускает настоящую функцию планировщика напрямую, без Redis. Поэтому production `/health/ready` закономерно возвращал 503. Тестовый gate проверяет завершённую инициализацию БД по закрытому fixture-файлу и HTTP `/health`. Production readiness, auth и config не изменены.

Браузерная проверка не подменяет интеграционную проверку Redis: полный backend-suite отдельно прошёл с живым Redis. Настройка постоянного browser workflow сохранена отдельно от одноразового publisher.
