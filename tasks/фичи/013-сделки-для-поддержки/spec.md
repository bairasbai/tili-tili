# Спека: Сделки свадьбы для поддержки

**Папка:** tasks/фичи/013-сделки-для-поддержки · **Заведена:** 2026-09-13 · **Статус:** одобрена владельцем 2026-09-13 («сделки без чатов»), в работе.
Закрывает `RELEASE-BLOCKERS.md` №24 (План §19.10 п. 5 «read-only просмотр сделки/проекта»).

## Зачем

Спор пары с подрядчиком о деньгах разбирается по обращению; поддержка видела только карточку свадьбы (название, дата, город) — ни
сделок, ни сумм, ни истории. Деньги — самое частое обращение, а разбирать его по скриншотам пары нельзя. Переписка остаётся закрытой:
решение владельца — «сделки без чатов».

## Границы

**Входит:** `GET /admin/weddings/{weddingId}/deals?reason=…` — список сделок свадьбы: слот, подрядчик из каталога по имени или свой
подрядчик по имени (без телефонов), состояние, цена, оплачено (та же формула, что у пары и подрядчика — `PAID_SUM`), даты брони и
отмены, история событий (кто: пара / подрядчик / система; откуда → куда; заметка). Причина обязательна, каждый запрос — строка журнала
`wedding.deals.view` с причиной. Экран карточки свадьбы: кнопка «Показать сделки» (отдельный запрос с той же причиной = отдельная запись
в журнале) → список.

**Не входит:** переписка пары ни с кем (решение владельца); телефоны своих подрядчиков и пары; правки сделок поддержкой; платежи по
отдельности (сумма «оплачено» достаточна для разбора; детализация — при первом реальном споре).

## Требования

- **FR-001** Контракт v0.36.0: путь и схема `SupportDeal`; 401/403/404/422.
- **FR-002** Бэкенд: `requireStaff`, `isUuid`, 404 у неизвестной свадьбы, журнал до ответа; `external_phone` не читается.
- **FR-003** Фронт `/admin/wedding`: после карточки — «Показать сделки» → `GET …/deals?reason` → список: «Фотограф · Студия Свет ·
  забронирован · 50 000 ₽ · оплачено 0 ₽», последнее событие датой; пусто — «Сделок у свадьбы нет»; отказ — словами; подпись экрана
  — «Список гостей и переписка поддержке не показываются».
- **FR-004** Тесты красные без фикса: бэкенд (501 до фикса) — имена, цены, история, нет телефонов, журнал, 422/403/404; фронт — до
  нажатия запроса нет, после — список из ответа.

## Решения

- В1 (владелец, 2026-09-13): сделки — да, переписка — нет.
- Р1 Отдельная кнопка, а не автозагрузка вместе с карточкой: каждое чтение чужих денег — своя строка журнала, и сотрудник нажимает её сам.
