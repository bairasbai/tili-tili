## Clean integration

Источник полезной платежной цепочки старого PR #3: `e7a27e4`…`6a106fd` (10 commits). Она перенесена настоящим `git cherry-pick` поверх текущего main с сохранением актуальных конфликтующих файлов 019/020 и последующим ручным объединением только платежной логики.

Ключевые конфликтные точки, объединённые вручную:
- `backend/src/routes/slots.ts`: старый `/pay` направлен в общий payment finance-core без отката booking-core 019;
- `app/src/pages/Wedding.tsx`: возвращены только reserve/category-limit UI 018-B, сохранены остальные 019/020 изменения;
- `app/src/lib/i18n.en.ts`: добавлены только отсутствовавшие payment EN-строки;
- `audit52/audit55`: guards синхронизированы с 17 денежными таблицами и API 0.51.0.

**Финальная база clean-кандидата:** `main` @ `744ebd80471f4e7004d6c43abd124221d47fe01c` (PR #13 docs 020 уже включён). PR #14 слит без изменения проверенного дерева: tree SHA head и merge-коммита одинаковый `75bc9b93260fdfe524a6dc89d88a1ff412f35a1e`.
