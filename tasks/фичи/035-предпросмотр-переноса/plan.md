# План реализации FR-009

1. Сверить проекцию с действующим переносом в `backend/src/wedding/reschedule.ts`. Использовать существующую формулу расчёта первой даты, правила фиксированных сроков и ограничение переноса броней ресурсов.
2. Добавить предпросмотр для пары. Подписывать его для текущей свадьбы, аккаунта, сессии и выбранной даты. Сверять последствия внутри существующей транзакции перед записью. Использовать действующую идемпотентность команды.
3. Показать последствия между выбором даты и её сохранением на экране «Мы». Сбрасывать подтверждение после смены даты, свадьбы или сессии. Сохранять штатный путь записи даты для существующих вызовов.
4. Проверить первую дату, перенос, недоступность и неизвестность, работу устаревшего предпросмотра и повтор запроса. Пройти сценарий через приложение и проверить, что после повторного входа показаны сохранённая дата и пересчитанные сроки.
