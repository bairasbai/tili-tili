# JWT при возврате сохранённого ответа пары

При cached replay токен пары мог истечь во время ожидания SQL, а сервер всё равно возвращал прежний приватный ответ. В семи callbacks добавлена проверка текущего JWT после последнего SQL: request/accept предложения, book/replace/cancel/pay слота и patch сделки. Теперь истёкший JWT получает 401/token_expired с no-store. Действующий повтор возвращает прежний JSON; запись, receipt, состояние сделки и платежа не выполняются заново.

Изменены только `backend/src/routes/deals.ts`, `offers.ts`, `slots.ts`; новый `backend/test/coupleReplayJwtExpiry.test.ts` зарегистрирован в `backend/vitest.serial.json`. Три импорта, семь проверок JWT. Денежные суммы, SQL бизнес-операций и провайдеры не изменены; реальные деньги не использовались.
