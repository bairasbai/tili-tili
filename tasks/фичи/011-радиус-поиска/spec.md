# Спека: Радиус поиска в каталоге

**Папка:** tasks/фичи/011-радиус-поиска · **Заведена:** 2026-09-13 · **Статус:** в работе (малая фича — без цикла вопросов: один экран,
один параметр; решения записаны ниже). Закрывает `RELEASE-BLOCKERS.md` №16. План §8.2 (каталог), §19.2.

## Зачем

Сервер умеет искать в радиусе от координат города (`radiusKm`, гаверсинус по `cities.lat/lon`), и по умолчанию контракта уже ищет в
**100 км** — экран об этом не знает: не даёт сузить до города или расширить до 300 км, а анкета из Бирска в выдаче «Уфа» ничем не
отличается от уфимской. Пара в Стерлитамаке (94 анкеты) должна видеть уфимских подрядчиков осознанно — «до 300 км», а не думать,
что их нет; пара в Уфе должна понимать, что фотограф из Бирска — в 80 км.

## Границы

**Входит:** переключатель радиуса на экране категории (`/search/:catId`): «только город» (0) · 50 · 100 (по умолчанию — как сервер)
· 300 км; параметр `radiusKm` в запросе; `Vendor.distanceKm` в ответе списка — километры от города поиска до города анкеты (0 —
тот же город, `null` — без `city` или без координат у одного из городов); карточка показывает «Бирск · 80 км»; подпись под
заголовком — «N рядом · до 100 км» / «N в городе».

**Не входит:** координаты у остальных 92 городов справочника (их привезёт геокодер — блокер владельца), геолокация телефона,
сортировка по расстоянию, радиус в других экранах (сравнение читает верх выдачи категории тем же запросом — радиус по умолчанию).

## Истории

### US1 — Пара расширяет или сужает поиск (P1) 🎯 MVP
**Как** пара из небольшого города, **я хочу** выбрать «до 300 км» и увидеть подрядчиков из областного центра, **чтобы** не решать,
что их нет. Дано: выбор радиуса → новый запрос с `radiusKm`; «только город» → точное совпадение; у анкеты из другого города —
расстояние в километрах; число в подписи — сколько показано и в каком радиусе.

## Требования

- **FR-001** Контракт: описание `radiusKm` (0 — только город; умолчание 100; города без координат — только точное совпадение);
  `Vendor.distanceKm` (integer, nullable). Генераторы.
- **FR-002** Бэкенд `GET /catalog/vendors`: `distanceKm` считается тем же гаверсинусом, что фильтр, от города `city`; без `city` —
  `null`; у анкеты (детали) — `null`. `radiusKm=0` — только `c.name = city`.
- **FR-003** Фронт: переключатель радиуса в строке фильтров (`select`, aria «Радиус поиска»), состояние экрана (умолчание 100),
  входит в ключ страницы (смена радиуса — новая первая страница); карточка — «<город> · N км» при `distanceKm > 0`; подпись —
  «N рядом · до R км» / «N в городе».
- **FR-004** Тесты красные без фикса: бэкенд — анкеты в Уфе, Бирске (≈80 км) и Стерлитамаке (≈123 км): радиус 100 включает Бирск с
  `distanceKm` 75…85 и не включает Стерлитамак; 0 — только Уфа; 300 — все три; без `city` — `distanceKm: null`. Фронт — запрос
  с `radiusKm`, смена радиуса → новый запрос, «· 80 км» на карточке, подпись.

## Критерии успеха

- **SC-001** Живьём: «Уфа» по умолчанию показывает бирские анкеты с «· 80 км», «только город» — без них, «до 300 км» — со
  Стерлитамаком «· 123 км».
- **SC-002** Полные наборы зелёные; `init.sh` exit 0.

## Решения (без вопросов владельцу — малая фича)

- Р1 Шаги радиуса 0 / 50 / 100 / 300 км; умолчание 100 — то, что сервер делает и сейчас (контракт `default: 100`), поэтому выдача
  по умолчанию не меняется, только становится видимой.
- Р2 Расстояние — целые километры от центра города до центра города (координаты справочника), не до площадки: адресов анкет нет.
- Р3 Города без координат (92 из 119) — как раньше: только точное совпадение имени; `distanceKm: null` — экран ничего не показывает.
