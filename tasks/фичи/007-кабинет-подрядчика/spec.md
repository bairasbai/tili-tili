# Спека: Кабинет подрядчика — чаты, настройки, анкета глазами пары

**Папка:** tasks/фичи/007-кабинет-подрядчика · **Заведена:** 2026-09-12 · **Статус:** сделана 2026-09-12 (итог — `tasks.md`; В1–В4 — `plan.md` §«Решения»). Экраны Плана §20.1: 53 «Чаты (подрядчик)», 56 «Настройки (подрядчик)»,
49 «Превью анкеты глазами пары».

## Зачем

Контур денег подрядчика — «заявка → переписка → сделка» — разорван посередине. Подрядчик отвечает на заявку с экрана
лида (первое сообщение уходит в чат с парой), а дальше переписку **продолжить не может**: маршрута чатов у `/vendor-app`
нет, нижняя навигация в кабинете выключена, пара пишет — подрядчик видит только уведомление. Настроек у подрядчика тоже
нет: ни выхода, ни сессий, ни push, ни удаления аккаунта — общий `/settings` из кабинета не открывается и говорит о свадьбе.
Свою анкету «как её видят пары» подрядчик посмотреть не может.

## Границы

**Входит:** маршруты `/vendor-app/chats` и `/vendor-app/chats/:id` на существующих экранах чатов (данные и права уже
есть — `GET /chats` отдаёт подрядчику его чаты с парами и общие чаты забронированных свадеб); карточка «Чаты» на
дашборде с числом непрочитанных; ссылка «Открыть чат» из заявки (контракт: `Lead.chatId`); нижняя навигация кабинета
(Кабинет · Сделки · Чаты · Настройки); `/vendor-app/settings` — общий экран настроек в режиме подрядчика (тема, язык,
push, сессии, выход, удаление аккаунта; без блоков свадьбы); «Посмотреть анкету глазами пары» → `/vendor/:id` для своей
анкеты, в том числе неопубликованной (сервер пускает владельца, экран говорит «пары её пока не видят»).

**Не входит:** новые виды чатов; вложения; настройки уведомлений подрядчика по видам (матрица §13 — отдельно); экраны 59–61.

## Истории

### US1 — Подрядчик ведёт переписку из кабинета (P1) 🎯 MVP
**Как** подрядчик, **я хочу** видеть список чатов и отвечать парам из кабинета, **чтобы** не терять заявки после первого
ответа. Дано: пара написала — тогда на дашборде карточка «Чаты · 1 новое», список показывает чат «Аня ♥ Боря» с непрочитанным,
переписка открывается и ответ уходит; из карточки заявки «Открыть чат» ведёт в этот же чат.

### US2 — У подрядчика есть настройки (P1)
**Как** подрядчик, **я хочу** выйти, посмотреть сессии, включить push и при необходимости удалить аккаунт, **чтобы**
управлять своим входом так же, как пара. Дано: активные сделки — удаление отвечает 409 `active_deals` словами сервера.

### US3 — Подрядчик видит анкету глазами пары (P2)
**Как** подрядчик, **я хочу** открыть свою анкету как её видит пара, **чтобы** проверить фото, цены и текст до
публикации. Дано: анкета не опубликована — тогда я вижу её с плашкой «пары её пока не видят», чужие — 404 как раньше.

## Требования

- **FR-001** `/vendor-app/chats` и `/vendor-app/chats/:id` рендерят `Chats`/`Chat` в оформлении кабинета (назад — в
  кабинет/в список), без блоков пары; список — из `GET /chats` как есть.
- **FR-002** Нижняя навигация кабинета на всех `/vendor-app*`: Кабинет (`/vendor-app`), Сделки (`/vendor-app/deals`), Чаты
  (`/vendor-app/chats`, бейдж непрочитанных из `GET /chats`), Настройки (`/vendor-app/settings`); на `/vendor-app/chats/:id` —
  скрыта, как у пары.
- **FR-003** Дашборд: карточка «Чаты с парами» — «N непрочитанных» только с ответом `GET /chats`; без ответа — «Загружаем…»/ошибка.
- **FR-004** Контракт: `Lead.chatId` (nullable) — чат заявки; экран заявки после ответа показывает «Открыть чат» → `/vendor-app/chats/{chatId}`.
- **FR-005** `/vendor-app/settings` — `Settings` в режиме подрядчика: тема, язык, push на устройстве и список подписок, сессии,
  «Выйти», «Выйти со всех устройств», «Удалить аккаунт» (409 `active_deals` — словами сервера); блоки свадьбы (отмена, пояс,
  город свадьбы) скрыты; ссылка «Посмотреть анкету глазами пары».
- **FR-006** `GET /catalog/vendors/{vendorId}` пускает владельца к своей неопубликованной анкете; ответ несёт `published`
  (уже есть у владельца) — экран `/vendor/:id` при `published: false` показывает плашку «Анкета не опубликована — пары её пока
  не видят» и не предлагает «Написать»/«Добавить в свадьбу» самому себе.
- **FR-007** Регрессии красные без фикса; карты и словарь той же итерацией.

## Критерии успеха

- **SC-001** Подрядчик доходит от заявки до ответа в переписке за два нажатия и видит ответ пары без уведомления.
- **SC-002** Ни одного экрана кабинета без выхода из него (навигация на каждом `/vendor-app*`).
- **SC-003** Полные наборы зелёные; `audit14`/`prod5` согласны с контрактом.

## Допущения

- **A1** Заголовки и права чатов подрядчика сервер уже считает (`outsider`, `wedding_title`): экран списка переиспользуется.
- **A2** Настройки уведомлений подрядчика по видам (лиды/сделки/чаты) — отдельная фича; здесь только push-тумблер.
