# WP03: промежуточная проверка идентичности и версии

Это исторический отчёт этапа ID/версии. Последующее локальное планирование блоков и актуальные проверки: [REPORT-PLANNING](REPORT-PLANNING.md). Открытые пункты ниже отражают состояние именно конца этапа версии, не текущую реализацию T005.

Дата: 2026-09-30. Полный WP03 **не принят**. Прикладные изменения пока не закоммичены/не опубликованы; main остаётся исходным ccd68fd. Production не затрагивался. Это проверка T002/T003 и миграции текущей версии, не замена FR-035–040, SC/NFR и остальных WP00–WP16.

## Реализовано локально

- Сохранение постоянных ID; атомарный отказ чужих/неизвестных/повторных ID, включая UUID-алиасы по регистру. Создание ID только для новых блоков.
- Версия программы, фактический автор и время изменения. Версия — bigint/строка, триггер увеличивает её на каждый изменённый блок. Историческая неизвестная дата/автор остаётся NULL.
- GET, PUT и autogen отдают версию/метаданные того же снимка. PUT требует If-Match: 428 без него, 409 timeline_conflict для устаревшего списка. Старые клиенты не обходят защиту. Shift и перенос даты инвалидируют редактор.
- Права проверяются повторно в транзакции после ожидания свадьбы: текущий аккаунт, сессия, членство/роль, архив и отмена.
- UI RU/EN показывает версию, автора и время; сохраняет поля и автоплан при отказе; обновление не переотправляет запись и не меняет версию предпросмотра. Принятый список/ID/ETag берётся из ответа PUT даже при неудачном последующем GET. Outdoor/forGuests не теряются.
- OpenAPI v0.53.0 и все генерируемые backend/frontend артефакты обновлены штатными генераторами.

## Что исправлялось в процессе проверки

- Первый full gate остановился на выводе TS-типа заголовков моков; фикстуры приведены к Record<string,string>, production fallback не добавлялся.
- Следующий full gate обнаружил старые backend-сценарии PUT без If-Match и отсутствующий timeline_conflict в описании контракта. Сценарии теперь читают реальный ETag, проверяют успешность fixture-save; контракт явно называет код. Проверки не ослаблялись.
- Первая репетиция миграции случайно не исключила новый файл: ignore-pattern node-pg-migrate сопоставляется с полным basename вместе с .cjs. Повтор выполнен на другой новой БД с явной проверкой отсутствия timeline_version до миграции; это подтверждает исторический, а не уже обновлённый fixture.
- Документы старого ID-only checkpoint являются историческими доказательствами; stale-save-probe не запускать как положительный тест новой защиты — он намеренно ожидал старую дыру.
