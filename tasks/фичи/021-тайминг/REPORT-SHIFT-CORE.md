## Первая Дата

Прежде rescheduleWedding назначал время по текущему sort из актуального шаблона. После удаления/перестановки/переименования блок мог получить чужие часы или день. Новый custom блок на позиции шаблона тоже получал выдуманное время. Explicit unknown duration получала прежнее template endsAt.

Миграция 1762000000000 добавляет nullable template_start/template_day_offset. POST /weddings сохраняет местные часы и смещение дня непосредственно у ID создаваемого шаблонного блока. PUT, удаление соседей, переименование, перестановка и автоплан их не переписывают. Первая дата использует только этот сохранённый источник, действующий пояс свадьбы и текущую известную duration_minutes. Уже заданное начало/fixed не меняются; unknown duration оставляет endsAt=null. Второй день сохраняет offset=1 независимо от позиции и дальнейшего изменения формата.

Для прежних undated строк источник не реконструируется по sort/имени/формату: этих полей недостаточно для доказательства происхождения. Миграция оставляет origin NULL и сообщает количество неизвестных через NOTICE. Первая дата не назначает им выдуманные часы; время задаётся явно через редактор. Реальное состояние production не читалось. Public API не получает новые внутренние колонки; контракт остаётся 0.54.0.

CHECK запрещает неполный origin, 24:00 и offset вне 0–366 (техническая граница, не обещание длительности мероприятия). Down отказывает при наличии записанного origin, чтобы не потерять его. Исторические поля, planning relations и metadata не переписываются.

## Расчёт Сдвига

backend/src/timeline/shift.ts — чистая функция над авторизованным снимком, не HTTP-обработчик. Она не читает БД, не пишет, не отправляет уведомлений и не проверяет сессию/ETag вместо будущего обработчика. Наличие eventId в её входном типе ещё не доказывает реальную модель мероприятий или её изоляцию на API.

- Область содержит явную дату/пояс; вариант event дополнительно отбирает постоянную идентичность мероприятия. Другой день, другое мероприятие, undated, fixed и уже начавшиеся блоки исключаются.
- Сдвиг от -240 до 240 целых ненулевых минут; секунды/миллисекунды сохраняются. Отрицательный сдвиг в прошлое или переход начала на другие местные сутки блокирует подтверждение.
- Зависимости проверяются по всему снимку, включая неизменяемые соседние блоки/другие мероприятия. Готовность предшественника + явный travel/buffer следующего должны помещаться до его начала. Эти минуты означают интервал до начала блока, не автоматический ETA.
- Ответственный и участники занимают время блока и его явно заданного предшествующего переезда/буфера. Общая ссылка или дополнительная server-resolved resource identity обнаруживает пересечение. Разные booked deals одного vendor должен нормализовать будущий серверный reader; сейчас unit fixture доказывает только расчёт при переданной одинаковой identity.
- Полуоткрытые интервалы могут соприкасаться; независимые параллельные активности не запрещены. Конфликт целиком вне затронутой области не блокирует действие. Неизвестная длительность/время зависимости/назначения и некорректная история не выдаются за безопасное отсутствие конфликта.
- Результат содержит before/after, исключённые блоки с причиной, конфликты, затронутые block IDs/references и явные перемещения. canConfirm=false при конфликте или пустом сдвиге. Ручное разрешение/роль координатора обязан обеспечить HTTP/UI этап; override или автоматическое разрешение не добавлены.

Это не проверка реальных bus routes, приглашённых по мероприятию, stale confirmation, idempotency, уведомлений или прав новых маршрутов: этих интеграций ещё нет.

## Следующий Шаг

Реальная модель/принадлежность мероприятия и её дата/пояс из сервера (стык WP04), связанный с ней timeline reader; versioned HTTP preview/confirm с access recheck после lock и запретом legacy обхода. Подтверждение должно заново вычислить eligibility фактическим временем, проверить source version и идемпотентно сохранить только preview blocks. Отказы/конфликты не пишут timeline/journal/notifications; ручное разрешение координатором и новый UI с явным подтверждением обязательны. Затем настоящие UI/API desktop/mobile и полный gate. T007–T011 и все остальные WP остаются открыты.
