## Фазы

### Фаза 1 — миграция и контракт (В1) · ~1 час
1. `bus_routes.deal_id uuid references deals(id) on delete set null`, `index (deal_id)`. `down` — снять.
2. Контракт v0.30.0: `BusRoute.dealId` (nullable, пишется парой), `BusRoute.carrier` (readOnly, nullable),
   `PATCH /weddings/{weddingId}/logistics/buses/{busId}` (тело — те же поля, все необязательные; 404/409/422),
   `busRoutes` у `GET /vendor/deals` items, снять `DayXBroadcast.notifiedGuests`; описания «зачем» у каждого поля.

### Фаза 2 — бэкенд · ~3 часа
1. `day.ts`: `POST …/buses` принимает `dealId` → проверка: сделка этой свадьбы, слот категории `transport`, не `cancelled`
   (422 `not_transport` / 409 `deal_cancelled`); `carrier` в `GET` пары и гостя (`left join deals d … left join vendors v`,
   `coalesce(v.name, d.external_name)`); `PATCH …/buses/{busId}` под замком строки: `seats < taken` → 409 `bus_full`.
2. Заметка подрядчику (`vendor_updates`) при создании/правке маршрута со сделкой из каталога — тем же механизмом, что у
   рассадки (`guests.ts`, столы).
3. `vendorCabinet.ts`: `busRoutes` у items — подзапрос по `bus_routes.deal_id`; без имён гостей.
4. Тесты `audit35`: маршрут со сделкой другой свадьбы → 422; с отменённой → 409; уменьшение мест ниже `taken` → 409;
   отмена сделки → `dealId: null`, `carrier: null`, записи гостей целы; кабинет видит `taken`, ответ не содержит имён и
   телефонов гостей; гость видит `carrier`.

### Фаза 3 — фронт · ~3 часа
1. `Logistics.tsx`: подпись перевозчика у маршрута («перевозчик убран», если `dealId` был и стал `null` — по `carrier === null && dealId === null`
   сервер даёт только текущее; подпись «без перевозчика»); в форме — «Перевозчик» (транспортные сделки из мозаики стора:
   `slot.categoryId === 'transport'` и сделка живая); «Изменить» → инлайн-форма → `PATCH`; `?deal=` из карточки сделки
   предвыбирает перевозчика и раскрывает форму.
2. `Tools.tsx` `DealView` (слот категории `transport`): блок «Маршруты для гостей» — список из `GET …/buses` (фильтр по
   `dealId`), «Добавить маршрут для гостей» → `/wedding/logistics?deal=<dealId>`; без маршрутов — честный текст.
3. `Invite.tsx` `GuestShuttle`: «Автобус №1 · Автобусы Уфы».
4. `VendorApp.tsx` сделки: «Маршрутов: N · записалось M из K» только при `busRoutes.length > 0`.
5. Тесты `audit33.test.tsx`; словарь; карты (`feature-006`).

## Открытые технические вопросы

- Транспортная сделка — только слот `transport`? Свой перевозчик, добавленный в другой слот (например, «Прочее»), связать
  нельзя — 422 с подсказкой «перевозчик заводится в слоте «Транспорт»». Принято как допущение A3 спеки.
- `PATCH` маршрута под замком `select … for update` — `seats` ниже `taken` ловит CHECK `bus_taken_bounded` (NOT VALID
  проверяет изменённую строку) → 409 `bus_full`; ранняя проверка в обработчике даёт текст.
