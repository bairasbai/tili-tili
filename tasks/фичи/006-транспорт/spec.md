# Спека: Транспорт — перевозчик как подрядчик, маршрут как его работа

**Папка:** tasks/фичи/006-транспорт · **Заведена:** 2026-09-12 · **Статус:** сделана 2026-09-12 (итог — `tasks.md`)

## Зачем

Владелец: «по моей задумке это должно быть как подрядчик — лимузин, общий автобус для гостей, частный перевозчик».
Сегодня в системе две несвязанные вещи: **сделка** с перевозчиком (слот «Транспорт», каталог, цена, дата, чат,
договор) и **маршрут** для гостей (`bus_routes`: название, точка сбора, время, места — гость записывается по ссылке).
Пара бронирует «Автобусы Уфы» как подрядчика и отдельно руками заводит «Автобус №1, 40 мест»; никто не подсказывает
ей сделать маршрут, перевозчик не знает, сколько гостей записалось, а в маршруте не написано, чей это автобус.
Лимузин пары — тоже сделка, но гостей не везёт: у него маршрута не будет, и это единственная разница.

## Границы

**Входит:** связь маршрута со сделкой (`bus_routes.deal_id`, необязательная — свой микроавтобус дяди остаётся без
сделки); имя перевозчика у маршрута для пары и гостя; кнопка «Добавить маршрут для гостей» в карточке сделки
категории «Транспорт»; выбор перевозчика в форме маршрута; правка маршрута (`PATCH` — сейчас только создать/удалить);
кабинет перевозчика видит маршруты своей сделки и число записавшихся (без имён и телефонов); заметка подрядчику при
создании/правке маршрута; контракт v0.30.0 (и снятие устаревшего `notifiedGuests`).

**Не входит:** типы транспорта как справочник (лимузин/автобус/такси — это сделка и её пакет, не поле маршрута);
маршруты, которые заводит сам перевозчик (у него нет прав на список гостей пары); SMS гостям.

## Истории

### US1 — Пара связывает маршрут с перевозчиком (P1) 🎯 MVP
**Как** пара, **я хочу**, чтобы маршрут для гостей знал, кто везёт, **чтобы** в логистике и у гостей стояло имя
перевозчика, а в карточке сделки было видно, что маршруты заведены.
1. Дано: забронирован «Автобусы Уфы» в слоте «Транспорт» — тогда в карточке сделки есть «Добавить маршрут для гостей»,
   маршрут создаётся с `dealId`, в логистике у маршрута подпись «Автобусы Уфы», в карточке сделки — «Маршрутов: 1 · 0/40».
2. Дано: маршрут заведён без перевозчика — тогда в форме маршрута можно выбрать сделку позже (`PATCH`), либо оставить
   «без перевозчика».
3. Дано: сделка с перевозчиком отменена — тогда маршрут остаётся (`deal_id → null`), подпись «перевозчик убран».

### US2 — Перевозчик видит свою работу (P2)
**Как** перевозчик, **я хочу** видеть в кабинете у сделки маршруты и число записавшихся, **чтобы** знать, сколько
машин и мест готовить; имён и телефонов гостей мне не нужно.

### US3 — Гость видит, кто везёт (P3)
**Как** гость, **я хочу** видеть у маршрута имя перевозчика, **чтобы** узнать автобус на точке сбора.

## Требования

- **FR-001** Миграция `bus_routes.deal_id uuid references deals on delete set null`, индекс; обратима.
- **FR-002** `POST`/`PATCH …/logistics/buses`: `dealId` — сделка этой свадьбы в слоте категории `transport`
  (иначе 422 `not_transport`), не отменённая (иначе 409 `deal_cancelled`); `PATCH …/buses/{busId}` — `name`, `from`,
  `time`, `seats` (не меньше `taken` — 409 `bus_full`), `dealId` (включая `null`).
- **FR-003** `BusRoute.carrier` (readOnly, nullable): имя подрядчика из каталога или `external_name`; отдаётся паре,
  команде и гостю (`GET /join/{t}/shuttle`).
- **FR-004** `GET /vendor/deals` items: `busRoutes: [{ id, name, from, time, seats, taken }]` у сделок в слоте `transport`
  (пусто у остальных); имён гостей нет.
- **FR-005** Заметка подрядчику (`vendor_updates`, как у рассадки): «Пара добавила маршрут «Автобус №1» — 40 мест» /
  «изменила маршрут» — только если у маршрута есть сделка и подрядчик из каталога.
- **FR-006** Экран сделки категории «Транспорт»: блок «Маршруты для гостей» (список с `taken/seats`, кнопка «Добавить
  маршрут для гостей» → форма маршрута с выбранным перевозчиком). Логистика: у маршрута подпись перевозчика, в форме —
  выбор «Перевозчик» из забронированных транспортных сделок (пусто — подсказка про слот «Транспорт»), «Изменить» у маршрута.
  Гость: подпись перевозчика у маршрута. Кабинет: «Маршрутов: N · записалось M из K» у транспортной сделки.
- **FR-007** Контракт v0.30.0: `BusRoute.dealId`/`carrier`, `PATCH …/buses/{busId}`, `busRoutes` у сделок кабинета,
  снятие `DayXBroadcast.notifiedGuests` (объявлен deprecated до v0.30); генераторы тем же коммитом.
- **FR-008** Регрессии красные без фикса; карты и словарь той же итерацией.

## Критерии успеха

- **SC-001** Пара с транспортной сделкой доходит до заведённого маршрута из карточки сделки в два нажатия.
- **SC-002** Отмена сделки не ломает маршрут и записи гостей; `GET …/buses` показывает «перевозчик убран».
- **SC-003** Перевозчик видит число записавшихся без единого имени/телефона в ответе (тест на отсутствие подстрок).
- **SC-004** Полные наборы зелёные, `init.sh` exit 0, `audit14`/`prod5` согласны с контрактом.

## Допущения

- **A1** Лимузин пары — сделка без маршрута; отдельного признака «для пары / для гостей» нет.
- **A2** Перевозчик маршруты не заводит: список гостей — данные пары.
- **A3** Тип транспорта живёт в названии пакета/сделки, не в схеме маршрута.
