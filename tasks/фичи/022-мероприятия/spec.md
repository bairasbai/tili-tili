# 022: Управление мероприятиями

## Источник и границы
Основание: `tasks/wedding-platform-master-plan/spec.md`, FR-035 и связанные FR-028/FR-030; `021-тайминг/REPORT-EVENT-MODEL.md`. Эта поставка закрывает только интерфейс управления уже существующими мероприятиями. Персональные приглашения, ответы по каждому человеку/мероприятию, логистика и полная приёмка WP04 остаются отдельной работой.

## Сценарии
1. Пара открывает мероприятия из тайминга, видит реальные название, тип, дату, место, часовой пояс и признак основного мероприятия. Неизвестные значения не заменяются догадками.
2. Пара создаёт дополнительное мероприятие, редактирует его метаданные, удаляет пустое дополнительное мероприятие после подтверждения. Основное не удаляется. Отказ удаления занятого мероприятия сохраняет данные и показывает причину сервера.
3. Команда с разрешённым доступом читает список без команд изменения. Ошибка доступа не выдаётся за пустой список. До определения роли изменения закрыты.
4. Одновременное изменение программы не затирается: форма связана с открытой версией; конфликт сохраняет черновик и требует явного открытия свежей версии. При потере связи нет автоматической повторной записи и нет ложного сообщения о сохранении.
5. Переключение свадьбы или уход с экрана не переносит старый черновик/поздний результат в другую свадьбу.

## Приёмка
- Создание/изменение/удаление сохраняются после перезагрузки; подтверждение показывается только после успешного ответа.
- Пустые дата, место и часовой пояс остаются неизвестными. Изменение одного поля не переписывает остальные, включая исторический часовой пояс.
- Основная дата доступна через существующий перенос в разделе «Мы», пока не утверждён другой сценарий. Изменение даты дополнительных мероприятий не обещает автоматического переноса блоков или уведомления гостей.
- RU/EN, клавиатура, мобильный и настольный экран; кнопки/форма/нижняя навигация не перекрываются.
- Полная локальная проверка с реальными тестовыми БД и браузером, без production и внешних отправок.

## Продолжение: Персональные Приглашения И RSVP
Основание: исходное ТЗ FR-027–031, FR-035. Для каждого человека хранится свой состав приглашённых мероприятий и свой ответ на каждое. Новое мероприятие не добавляется всем автоматически. Прежний ответ относится только к основной программе и сохраняется при переходе.
До общего срока гость меняет свой ответ; после срока требуется обращение к организатору, а не молчаливая перезапись. Правка пары обозначается как внесённая организатором. Гостевая ссылка показывает только мероприятия людей этого приглашения, без других приглашённых, бюджета и чужих ответов. Неизвестный срок остаётся неизвестным, не заменяется датой свадьбы.
Эти требования ещё не объявлены реализованными; CRUD-поставка опубликована в PR25, merge04a8355182467a93d9c10499bf4a11dbd6de3d6b.

- D1. Единый источник ответа на мероприятие остаётся `event_guest_participation` (030); вторую таблицу ответов не заводим.
- D2. Срок ответа и персональный RSVP — только для дополнительных мероприятий (`is_main=false`). Основной RSVP (`POST /rsvp/{guestToken}`) и его эффекты (автобус/гостиница/стол/меню) не меняются; срок у основного мероприятия — вне T012.
