# План 022

Канонический контракт: `Тили-тили/Тили-тили_API_openapi.yaml`, операции `/weddings/{weddingId}/events` и `/{eventId}`, схема WeddingEvent. Не дублировать серверные правила и не менять API/миграции ради интерфейса.

1. Регрессионный свидетель передачи If-Match для DELETE до исправления клиента. Типизированные обёртки на существующих путях/телах из schema.ts; расширение delete опциями совместимо с прежними вызовами.
2. Отдельный ленивый маршрут `/wedding/events`, вход из тайминга. Снимок списка/ETag и роль из `/weddings`; неизвестная роль закрывает запись. Компонент привязан ключом к свадьбе.
3. Доступный общий Dialog, реальные формы create/patch и подтверждение delete. PATCH только изменившимися полями. Черновик и ETag захватываются вместе, конфликт/неясный сетевой исход блокирует повтор до явного открытия свежего снимка. После успеха перечитать сервер; не добавлять оптимистические строки.
4. Unit-регрессии: роли, неизвестные поля/ETag, конфликт, поздний ответ, удаление, RU/EN, ошибки. Полный init.sh на свежей мигрированной БД; actual Chromium на production preview, скриншоты и геометрия.
5. Карты, отчёт, handoff и scoped публикация с CI. Не объявлять WP04 или все WP00–WP16 завершёнными.
