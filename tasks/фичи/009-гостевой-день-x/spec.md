# Спека: Гостевой день X — программа, стол, маршрут, контакты и чат дня для гостя

**Папка:** tasks/фичи/009-гостевой-день-x · **Заведена:** 2026-09-12 · **Статус:** одобрена 2026-09-12, в работе (В1–В3 — `plan.md` §«Решения»). Экраны Плана §20.1: 59 «Гостевой день X»,
60 «Чат дня (гость)». План §8.8: «в день X — тайминг дня (только гостевые блоки), адрес и маршрут, «ваш стол №7»,
контакты координатора (не жениха!), дресс-код, чат дня».

## Зачем

Гость сегодня видит на `/invite` место, трансфер и отели — и всё. В сам день ему нужно другое: во сколько церемония, где его
стол, какой автобус и во сколько, кому звонить, если опоздал, — и общий канал «автобус от ЗАГСа задерживается на 10 минут»,
чтобы не звонили жениху (План §8.8, §13.1 п. 4). Чат дня X у пары есть (`kind='day'`, открывается накануне) — гостя в нём нет.

## Границы

**Входит:** `GET /join/{guestToken}/day` — программа дня (только блоки, отмеченные «для гостей»), адрес, дресс-код, стол
гостя, его маршрут с перевозчиком, контакт координатора; переключатель «Показывать гостям» у блока тайминга (миграция
`timeline_events.for_guests`); чат дня для гостя — чтение и отправка по токену в общий чат дня X (миграция
`messages.guest_id` + имя гостя в ответе), открыт с кануна свадьбы по день после; пара и команда видят реплики гостей с
именем в том же чате; экран `/invite` получает раздел «День свадьбы» (виден с кануна).

**Не входит:** фото гостя в альбом (хранилище — блокер №3), push гостям (канала нет), прогноз погоды, удаление реплик
модератором (отдельный путь — хвост), «построить маршрут» в навигаторе — ссылка по адресу, без гео.

## Истории

### US1 — Гость видит свой день (P1) 🎯 MVP
**Как** гость, **я хочу** в день свадьбы открыть ссылку и увидеть программу, свой стол, автобус и кому звонить, **чтобы**
не дёргать пару. Дано: до кануна — раздела нет (есть приглашение как раньше); с кануна — «День свадьбы»: программа
(гостевые блоки в поясе места), «Ваш стол: у окна», «Автобус №1 · 14:30 · Автобусы Уфы», «Координатор: Мария, +7…»,
дресс-код; без стола/автобуса/координатора — честные «пока не назначен».

### US2 — Пара выбирает, что видят гости (P1)
**Как** пара, **я хочу** снять галочку «Показывать гостям» у «Сборы невесты», **чтобы** гости видели только программу
праздника. Дано: новый блок — по умолчанию виден; снятая галочка — блока нет у гостя, но есть у команды.

### US3 — Гость пишет в чат дня (P2)
**Как** гость, **я хочу** прочитать чат дня и написать «автобус задерживается», **чтобы** все гости и координатор знали.
Дано: чат открыт с кануна по день после; реплика гостя приходит паре и команде с именем гостя; до открытия — «чат
откроется 13 июня».

## Требования

- **FR-001** Миграция 1: `timeline_events.for_guests boolean not null default true`; `TimelineEvent.forGuests` в контракте
  (пишется парой в `PUT …/timeline`, читается всеми); экран тайминга — галочка у блока.
- **FR-002** Миграция 2: `messages.guest_id uuid references guests on delete set null`; `CHECK` — у реплики либо
  `sender_id`, либо `guest_id`, либо ни того ни другого (система/свой подрядчик/Тиль), но не оба; `Message.guestName`
  (nullable) в контракте — имя гостя у его реплик.
- **FR-003** `GET /join/{guestToken}/day` (контракт, новый): `{ date, tz, venue, dressCode, dressNote, timeline: TimelineEvent[]
  (только for_guests), table: { name } | null, bus: BusRoute | null, coordinator: { name, phone } | null, chat: { open: boolean,
  opensAt } }`; 410 у отозванного токена.
- **FR-004** `GET /join/{guestToken}/day-chat/messages` (курсор, как у чатов) и `POST …/day-chat/messages` `{ text }` —
  только в окне [канун 09:00 по поясу места; конец дня после]; вне окна 423 `chat_closed_for_guests` с `opensAt`;
  реплика пишется в чат `kind='day'` свадьбы с `guest_id`; пара/команда получают её в `GET /chats/{id}/messages` с
  `guestName`; уведомление команде — как от участника.
- **FR-005** `/invite`: раздел «День свадьбы» с кануна (по `tz` места): программа, стол, автобус, координатор, дресс-код,
  «Открыть чат дня» → экран чата гостя (лента, поле, опрос раз в 30 с как у пары); до открытия — «откроется <дата>».
- **FR-006** Регрессии красные без фикса; карты и словарь той же итерацией; `audit14`/`prod5` согласны с контрактом.

## Критерии успеха

- **SC-001** Гость без аккаунта видит программу, стол, автобус и координатора одним запросом; «Сборы» со снятой галочкой у
  него не появляются.
- **SC-002** Реплика гостя видна паре в чате дня с именем; вне окна — 423, не 500 и не молчание.
- **SC-003** Полные наборы зелёные; `init.sh` exit 0.

## Допущения

- **A1** Координатор — участник свадьбы с ролью `coordinator`; его телефон показывается гостям (он для этого и нужен —
  План §8.8); имя — из профиля. Нет координатора — блока нет.
- **A2** Гость пишет от своего имени из списка; редактировать/удалять реплики гость не может.
- **A3** Окно чата — по поясу места свадьбы; те же 09:00 кануна, что у `opens_at` чата дня.
