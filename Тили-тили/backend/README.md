# Тили-тили — бэкенд

Сервер по `BACKEND-PLAN.md`: все пути контракта реализованы (число путей и
операций — в `CLAUDE.md`). Выкладка — `DEPLOY.md` в корне (состав `deploy/`),
порядок включения переменных окружения — там же, §1.

## Быстрый старт

```bash
corepack pnpm install --node-linker=hoisted
cp .env.example .env          # заполнить DATABASE_URL и REDIS_URL
docker compose up -d db redis
pnpm run migrate up
pnpm run dev                  # http://localhost:3000/health
```

## Команды

| Команда | Что делает |
|---|---|
| `pnpm run dev` | сервер с перезапуском по изменениям |
| `pnpm run verify` | типы + тесты + линт — определение «готово» |
| `docker compose up -d db redis` | поднять PostgreSQL и Redis локально |
| `pnpm run gen` | список путей и типы из контракта |
| `pnpm run migrate up` | накатить миграции |
| `pnpm run migrate:fresh` | репетиция: все миграции с нуля в чистой схеме `tili_fresh` той же базы (создаётся и удаляется), число таблиц и категорий, состояние проверок CHECK — перед каждой выкладкой (`DEPLOY.md` §2) |
| `pnpm run build && pnpm start` | прод-сборка |

Если бинарники в `node_modules/.bin` пропали (последствие сломанного npm) —
запускать напрямую: `node node_modules/vitest/vitest.mjs run`,
`node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit`,
`node node_modules/eslint/bin/eslint.js .`.

## Что здесь важного

**Контракт — источник правды, и это проверяется.** `scripts/gen-contract.mjs`
читает `../Тили-тили_API_openapi.yaml` и пишет `src/contract/paths.generated.ts`.
Файл коммитится; `test/contract-sync.test.ts` падает, если контракт ушёл вперёд,
а генерацию забыли. Править сгенерированный файл руками нельзя.

**404 и 501 — разные ответы.** `404` значит «такого адреса нет» — фронт ищет
опечатку у себя. `501` значит «адрес согласован, обработчик будет на этапе N» —
фронт ждёт бэкенд. Пока разница не проведена, любая ошибка фронта выглядит как
отставание сервера.

**Один формат ошибки на весь API:** `{ error: { code, message } }`, для 422 —
плюс `fields`. Стектрейсы и тексты драйвера наружу не уходят; в теле 500 есть
идентификатор запроса, по нему жалоба находится в логах.

**Пагинация по курсору, не по offset.** Offset на живых данных показывает одну
и ту же запись на двух страницах. Курсор — `base64url(sortValue|id)`; второй
ключ обязателен, иначе порядок между записями с равной датой не определён.

**Тесты с живыми службами идут только при заданных подключениях.**
`TEST_DATABASE_URL` и `TEST_REDIS_URL` включают набор `test/integration.test.ts`:
миграции, `citext`, `gen_random_uuid`, `/health/ready` → 200. Без них набор
пропускается — и пропуск видно в выводе, поэтому «зелёно без базы» нельзя
спутать с «база проверена». В CI службы подняты, там он идёт всегда.

```bash
docker compose up -d db redis
pnpm run migrate up
TEST_DATABASE_URL=postgres://tili:tili@localhost:5432/tili TEST_REDIS_URL=redis://localhost:6379 pnpm test
```

**Два разных health.** `/health` — процесс жив, всегда 200, по нему
перезапускают контейнер. `/health/ready` — 503, если база или Redis недоступны,
по нему балансировщик выводит машину из ротации. Ронять контейнер из-за упавшей
базы нельзя: приложение уйдёт в цикл перезапусков и не поднимется, когда база
вернётся.

**Инварианты живут в БД, не в коде.** Гонки за дату, за подарок и за место
в автобусе закрываются ограничениями PostgreSQL (раздел 2 плана), а не
проверками в обработчике. Это же условие дешёвого разворота на другой язык:
логики в ORM-хуках нет, обработчики не знают про Fastify глубже `request/reply`.

## Зависимости и лок-файл

Здесь основной лок — **`pnpm-lock.yaml`**, в отличие от `app/`, где основной
`package-lock.json`. Причина: `npm install` на этой машине падает
(`Exit handler never called!`, Node 25 + npm 11.12.1, ERR-0006), а бэкенд —
новый пакет без истории npm. В образе стоит Node 22 LTS, там этой проблемы нет.

## Образ

`docker build -t tili-backend .` — многостадийная сборка на `node:22-alpine`.
Внутри образа лежит `.npmrc` с `minimum-release-age=0`. pnpm по умолчанию
отвергает пакеты, опубликованные несколько часов назад, — защита от подменённой
версии при интерактивной установке. В образе ставится закоммиченный лок-файл,
версии в котором уже отобраны, а гейт превращается в «выкат невозможен сутки
после релиза любой зависимости». Локально `pnpm add` защиту сохраняет.

Версия pnpm в образе закреплена (`corepack prepare pnpm@10.34.5`): иначе corepack
тянет свежайшую, и она может читать лок-файл строже той, которой он собран.

## Тиль: провайдеры модели

Тиль (ИИ-помощник пары, чат `kind=tilly`) говорит с любой моделью по одному
протоколу — OpenAI-совместимые chat completions (`POST {TILLY_BASE_URL}/chat/completions`).
Своей зависимости нет: клиент — `fetch` в `src/tilly/model.ts`. Без настройки Тиль
отвечает честной заглушкой «пока без ИИ», и сервер стартует в любом окружении.

| `TILLY_PROVIDER` | что это | `TILLY_BASE_URL` (умолчание) | `TILLY_API_KEY` | `TILLY_MODEL` (умолчание) |
|---|---|---|---|---|
| `openrouter` | openrouter.ai — сотни моделей одним ключом, есть бесплатные | `https://openrouter.ai/api/v1` | обязателен (openrouter.ai/keys) | `openrouter/free` — маршрутизатор бесплатных; через запятую — запасные |
| `ollama` | локальная модель на своём сервере | `http://127.0.0.1:11434/v1` | не нужен | `hermes3` (Hermes 3 от Nous; любая из ollama.com/library) |
| `openai` | любой OpenAI-совместимый сервер: vLLM, llama.cpp, LM Studio | обязателен | по серверу | обязателен |

Локальная модель: на сервере `curl -fsSL https://ollama.com/install.sh | sh`, затем `ollama pull hermes3`
(8B — от 8 ГБ RAM; 70B — GPU/ощутимо больше), в `.env` — `TILLY_PROVIDER=ollama`. Данные свадеб при этом
не покидают сервер. Бесплатные модели OpenRouter — со своими пределами (~20 запросов в минуту, 50 в сутки на
ключ без кредитов, 1 000 — после покупки $10) и без гарантии качества русского языка: модель за маршрутизатором
меняется; при отказе провайдера пара видит «Тиль временно без ИИ», а вызов ложится в `tilly_usage` с
`outcome=failed`. Лимит на свадьбу — `TILLY_DAILY_LIMIT` (50 реплик в сутки, План §18); расход — в
`GET /admin/metrics` (`llm`). В модель уходят только данные проекта без телефонов, e-mail и комментариев
гостей (`src/tilly/context.ts`).

## Секреты

Только переменные окружения. В репозитории лежит `.env.example` без значений;
`.env` в `.gitignore`. Секреты подписи токенов генерировать
`openssl rand -base64 48`, разные для access и refresh.
