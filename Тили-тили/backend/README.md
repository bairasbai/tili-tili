# Тили-тили — бэкенд

Fastify API и фоновые задачи. Контракт находится в [OpenAPI](../Тили-тили_API_openapi.yaml),
сборка сервера — в [src/app.ts](src/app.ts), настройки — в [src/config.ts](src/config.ts).
Доступность функций с внешними провайдерами описана в [инструкции выпуска](../../DEPLOY.md).

## Быстрый старт

Используй Node 22 и выделенные PostgreSQL и Redis. При первом запуске создай
`.env` по [шаблону](.env.example) и укажи адреса служб в `DATABASE_URL` и
`REDIS_URL`. Для связки с локальным Vite нужен `PORT=3001`.

```bash
corepack pnpm@10.34.5 install --frozen-lockfile --node-linker=hoisted
corepack pnpm@10.34.5 run migrate up
corepack pnpm@10.34.5 run dev
```

## Что здесь важного

**Контракт — источник правды.** При изменении OpenAPI запусти `pnpm run gen`.
[CI](../../.github/workflows/ci.yml) сравнивает четыре сгенерированных файла
с версией в Git. Вручную эти файлы не редактируются.

**Ошибки API.** Для обработки смотри HTTP-статус и `error.code`.
`404` может означать, что ресурс недоступен этому пользователю.
`501` используется в том числе для функций, которым требуется настройка,
например для Web Push без VAPID. [Маршруты уведомлений](src/routes/notifications.ts)

**Один формат ошибки на весь API:** `{ error: { code, message } }`, для 422 —
плюс `fields`. Стектрейсы и тексты драйвера наружу не уходят; в теле 500 есть
идентификатор запроса, по нему жалоба находится в логах.

**Пагинация по курсору, не по offset.** Offset на живых данных показывает одну
и ту же запись на двух страницах. Курсор — `base64url(sortValue|id)`; второй
ключ обязателен, иначе порядок между записями с равной датой не определён.

**Тесты с живыми службами идут только при заданных подключениях.**
`TEST_DATABASE_URL` и `TEST_REDIS_URL` включают набор `test/integration.test.ts`:
миграции, `citext`, `gen_random_uuid`, `/health/ready` → 200. Без них набор
пропускается — и пропуск видно в выводе, поэтому «зелёно без базы» нельзя
спутать с «база проверена». В CI службы подняты, там он идёт всегда.

Для одного набора владелец тестового стенда передаёт `TEST_DATABASE_URL` и
`TEST_REDIS_URL`. Выбери разрешённый набором порт одноразовой PostgreSQL 15432
или 55432 и укажи его в `TILI_DISPOSABLE_PG_PORT`. Системные службы на 5432 и
6379 принадлежат другим задачам. После сверки адресов и миграций из каталога
бэкенда можно выполнить `node node_modules/vitest/vitest.mjs run test/integration.test.ts`.

Для общей проверки с фронтендом запусти [`bash init.sh`](../../init.sh) из
корня репозитория после миграций в выделенной БД. Передай `TEST_DATABASE_URL`
и `TEST_REDIS_URL`, чтобы включить наборы с живыми службами.

Для тестов поиска городов на Windows проверена база PostgreSQL 16 с ICU
и локалью `ru-RU`. При создании новой одноразовой БД через `createdb` используй
`--template=template0 --locale-provider=icu --icu-locale=ru-RU`. Перед
миграциями проверь преобразование регистра в этой базе.

```sql
SELECT lower('Уфа') = 'уфа' AS city_case_fold_ok;
```

Ожидаемый результат — `true`. В проверенной Windows-базе с libc `C`
функция `lower()` оставляла «У» заглавной. [Миграция городов](migrations/1757100000000_auth_and_geo.cjs)
вычисляет и хранит `cities.name_norm` через `lower()`, поэтому при
`false` подготовь новую тестовую БД с рабочим преобразованием регистра до
применения миграций.

Полный экосистемный прогон ведёт оркестратор по [правилам проекта](../../CLAUDE.md#4-команды).
Для него требуются выделенная база на 15432, одинаковые `DATABASE_URL`
и `TEST_DATABASE_URL`, а также допуск конкретных наборов к тестовому окружению.
При отказе допуска к пути checkout или каталогу БД используй результаты
штатных заданий [серверного CI](../../.github/workflows/ci.yml) на проверяемом
коммите. Там запускаются допуск исходников и репетиция исторических миграций.
В выделенном Windows-дереве `wp11-manual-20261120` историческая
проверка создаёт собственную временную папку в корне `.unlazy` и удаляет
её после успешного завершения этого шага.

**Два разных health.** `/health` — процесс жив, всегда 200, по нему
перезапускают контейнер. `/health/ready` — 503, если база или Redis недоступны,
по нему балансировщик выводит машину из ротации. Ронять контейнер из-за упавшей
базы нельзя: приложение уйдёт в цикл перезапусков и не поднимется, когда база
вернётся.

**Инварианты живут в БД, не в коде.** Гонки за дату, за подарок и за место
в автобусе закрываются ограничениями PostgreSQL (раздел 2 плана), а не
проверками в обработчике. Это же условие дешёвого разворота на другой язык:
логики в ORM-хуках нет, обработчики не знают про Fastify глубже `request/reply`.

## Образ

`docker build -t tili-backend .` — многостадийная сборка на `node:22-alpine`.
Внутри образа лежит `.npmrc` с `minimum-release-age=0`. pnpm по умолчанию
отвергает пакеты, опубликованные несколько часов назад, — защита от подменённой
версии при интерактивной установке. В образе ставится закоммиченный лок-файл,
версии в котором уже отобраны, а гейт превращается в «выкат невозможен сутки
после релиза любой зависимости». Локально `pnpm add` защиту сохраняет.

Версия pnpm в образе закреплена (`corepack prepare pnpm@10.34.5`): иначе corepack
тянет свежайшую, и она может читать лок-файл строже той, которой он собран.

## Тиль: провайдеры модели

Тиль (ИИ-помощник пары, чат `kind=tilly`) говорит с любой моделью по одному
протоколу — OpenAI-совместимые chat completions (`POST {TILLY_BASE_URL}/chat/completions`).
Своей зависимости нет: клиент — `fetch` в `src/tilly/model.ts`. Без настройки Тиль
отвечает честной заглушкой «пока без ИИ», и сервер стартует в любом окружении.

| `TILLY_PROVIDER` | что это | `TILLY_BASE_URL` (умолчание) | `TILLY_API_KEY` | `TILLY_MODEL` (умолчание) |
|---|---|---|---|---|
| `openrouter` | openrouter.ai — сотни моделей одним ключом, есть бесплатные | `https://openrouter.ai/api/v1` | обязателен (openrouter.ai/keys) | `openrouter/free` — маршрутизатор бесплатных; через запятую — запасные |
| `ollama` | локальная модель на своём сервере | `http://127.0.0.1:11434/v1` | не нужен | `hermes3` (Hermes 3 от Nous; любая из ollama.com/library) |
| `openai` | любой OpenAI-совместимый сервер: vLLM, llama.cpp, LM Studio | обязателен | по серверу | обязателен |

Локальная модель: на сервере `curl -fsSL https://ollama.com/install.sh | sh`, затем `ollama pull hermes3`
(8B — от 8 ГБ RAM; 70B — GPU/ощутимо больше), в `.env` — `TILLY_PROVIDER=ollama`. Данные свадеб при этом
не покидают сервер. Бесплатные модели OpenRouter — со своими пределами (~20 запросов в минуту, 50 в сутки на
ключ без кредитов, 1 000 — после покупки $10) и без гарантии качества русского языка: модель за маршрутизатором
меняется; при отказе провайдера пара видит «Тиль временно без ИИ», а вызов ложится в `tilly_usage` с
`outcome=failed`. Лимит на свадьбу — `TILLY_DAILY_LIMIT` (50 реплик в сутки, План §18); расход — в
`GET /admin/metrics` (`llm`). В модель уходят только данные проекта без телефонов, e-mail и комментариев
гостей (`src/tilly/context.ts`).

## Секреты

Основа приватных фотографий032-A — `src/media/`: точный presigned POST для quarantine, bounded S3 GET, immutable clean PUT, ClamD INSTREAM с общим сроком15с и перекодирование одиночного JPEG/PNG/WebP в WebP без метаданных. Вход/выход до10МиБ, вход до40млн пикселей и8192 на сторону; SDK error/control bodies отдельно ограничены64КиБ до десериализации. Служебные ошибки и секреты наружу не передаются. Все `MEDIA_*` из `.env.example` по умолчанию пусты; частичная настройка отклоняется.

Управляемый сервис обслуживает фото портфолио, кадры гостевого альбома, PDF
редакций договора и файлы сдачи заказа. Он выдаёт ограниченный POST и
отдельно проверяет результат. В портфолио добавляется только файл в состоянии
`ready`. При сохранении анкеты внешние ссылки и их ID сохраняются. Выдача
новой загрузки без полной конфигурации отвечает `501 storage_not_configured`.
Текущая приёмка описана в [плане](../../tasks/wedding-platform-master-plan/delivery.md).

Schema99 добавляет media_uploads и durable media_objects. Quarantine и каждый immutable clean candidate регистрируются до внешней записи; inflight/uncertain PUT не объявляются очищенными по одному DELETE ACK. Ключ, storage namespace, writer nonce и obligation version сохраняются после удаления пользователя. Задача media-cleanup идёт раз в минуту; после8 попыток неясное обязательство остаётся failed для оператора. Экспорт содержит безопасное состояние, без storage keys/grants. Доставка повторно проверяет права и hash и удерживает максимум8 buffered HTTP-ответов до finish/close (deadline30с).

Включение требует операторской квалификации приватности bucket/ACL, exact POST условий, CORS, актуального ClamAV engine/signatures, часов, lifecycle и восстановления. MEDIA_S3_POST_MAX_SECONDS — подтверждённый абсолютный предел1..60с от принятия POST до возможного commit, включая медленное тело и очереди; само значение env этого не доказывает. Durable external_until не раньше policy expiry + этот предел + отдельный запас120с. До квалификации MEDIA_* остаются пустыми. Local HTTP/TCP fixtures не подтверждают реальный bucket, engine или устройства; инструкция — RUNBOOK.md §9.

Только переменные окружения. В репозитории лежит `.env.example` без значений;
`.env` в `.gitignore`. Секреты подписи токенов генерировать
`openssl rand -base64 48`, разные для access и refresh.
