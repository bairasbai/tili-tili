# Тили-тили — Карта экранов и элементов (SSOT для разработки)

> **Назначение.** Этот файл — карта всех экранов, блоков и интерактивных элементов приложения. Любой ИИ-разработчик (Kimi K3, Claude Code или другой) обязан прочитать его перед изменением UI.
>
> **Правило R-MAP (обязательное):** каждый раз, когда добавляется/изменяется/удаляется экран, блок или кнопка — этот файл обновляется **в той же итерации**, а событие фиксируется в журнале изменений (внизу файла). Файл хранится рядом с планом: `/mnt/agents/output/Тили-тили_Карта_экранов.md`.
>
> Версия карты: **2.0** · обновлено 2026-09-19 · тело разделов 1–8 собрано из кода (аудит, блок 5; пересобрано 2026-09-07 после фичи 001 «Админка» 2026-09-11 после ревью старого кода и ревью фиксов, 2026-09-12 после фич 005–010, 2026-09-13 после фич 011–014, 2026-09-18 после ревью 015, его живой проверки, сверки планов и корзины 1, 2026-09-19 после живого обхода ролей); раздел 0 — архитектура.

## 0. Архитектура навигации

### 0.1. Каркас
- `App.tsx → Shell` — единый роутер. `app-shell` ограничивает ширину 430px (мобильный канвас).
- **TabBar** (плавающая стеклянная панель снизу) скрывается на: `/`, `/quiz`, `/invite`, `/auth`, `/dayx`, `/assistant`, чатах (`/us/chats/:id`), кабинете подрядчика (`/vendor-app*`).
- TabBar: `Главная /home` · `Поиск /search` · центральная 💍 `/wedding` · `Чаты /us/chats` · `Мы /us`.
- Guard: `/home` без онбординга → редирект на `/`. `*` → `/home` (если онбординг пройден) иначе `/`.
- **Гейт устаревшего согласия** (F4, RL-1, `review016-tail6`): вошедший с флагом `tt_consent_outdated` заменяет `<Suspense><Routes>` целиком на `ConsentGate` (`pages/Consent.tsx`) — не отдельный маршрут, поэтому «Назад» и deep-link его не обходят; таб-бар при этом тоже скрыт. Свободны (личность гостя, не аккаунта, или сами документы): `/legal/offer`, `/legal/privacy`, `/invite`, `/invite/*`, `/i/*`, `/guest-vendor/*`, `/gifts`.

### 0.2. Store (`src/lib/store.tsx`) — состояние приложения
- Источник правды — сервер. В `localStorage` живёт только свойство устройства: тема, язык, город по умолчанию, факт онбординга, идентификатор свадьбы (`tt_wedding_id`, восстанавливается через `GET /weddings`) и последняя известная дата (`tt_wedding_date`, при расхождении выигрывает сервер).
- Мозаика команды (`slots`) читается с сервера (`GET /weddings/{weddingId}/slots`), состояние загрузки хранится явно: `slotsState` = `idle | loading | ready | error` (R-179).
- Записи через стор уходят на сервер и перечитывают мозаику: `bookVendor` → `POST …/slots/{slotId}/book`, `cancelBooking` → `POST …/cancel`, `paySlot` → `POST …/pay`, `advanceDealTo` → `PATCH /deals/{dealId}`, `bookExternal` → `POST …/external`, `inviteExternal` → `POST …/external/invite`, `removeExternalVendor` → `DELETE …/external`, `setWeddingDate` → `PATCH /weddings/{weddingId}`, `toggleFav` → `PUT/DELETE /me/favorites/{vendorId}` (откат только своего сердечка при отказе). `bookVendor` несёт `packageId` выбранного пакета (ревью 015, FB1).
- Заметки (`/notes`) — на сервере (`GET/POST/DELETE /weddings/{weddingId}/notes`, фича 014); в `localStorage` остаются только заметки прежней версии до переноса одной кнопкой.
- Смерть сессии (сервер отверг refresh) — событие `onSessionExpired` из `lib/api/client.ts`: стор зовёт `forgetSession`, как при выходе кнопкой (ревью 015, FA1), — переходом (`startTransition`), чтобы переход на вход, начатый тем же событием, лёг в тот же кадр (F4-F-G6r5-01/02). Избранное синхронизируется с сервером при старте и после входа (`weddingsState === 'ready'`).
- Устаревшее согласие (403 `consent_outdated`, тот же код у живого канала) — событие `onConsentOutdated` из `lib/api/client.ts` и флаг `tt_consent_outdated` в `localStorage` (переживает перезагрузку и офлайн); `Shell` подписан и держит гейт, вторая вкладка узнаёт об этом через `storage` (F4, RL-1).
- i18n: `lib/i18n.ts` — `t(s)`, словарь `lib/i18n.en.ts` (ключ — русская строка, R-07). PWA: `public/sw.js`, регистрация в `main.tsx`.

### 0.2.1. География (`src/lib/cities.ts`)
- Плоский список `City { n, r, d?, big? }`: n — название, r — субъект РФ, d — район, big — в «Популярных».
- Покрытие: крупные города РФ + **все райцентры Башкортостана** (Сибай, Баймак, Белорецк, Мелеуз, Туймазы, Давлеканово и др.) + соседние регионы (Челябинская, Оренбургская обл., Татарстан, Пермский край…).
- `searchCities(q, limit)` — поиск по подстроке (ё→е), префиксные совпадения первыми; ищет и по району.
- `POPULAR_CITIES` — стартовый экран пикера.
- **Компонент `CityPicker`** (`components/CityPicker.tsx`) — полноэкранный оверлей: живой автопоиск, группа «Башкортостан», популярные чипы, геолокация (navigator.geolocation → `nearestCity`, haversine по `CITY_COORDS`), пустое состояние. Используется в квизе и настройках.
- **Боевой план**: заменить/дополнить Яндекс Геокодер API (`geocode-maps.yandex.ru/1.x/?kind=locality&q=…`); контракт бэкенда: `GET /geo/cities?q=… → [{ id, name, region, district, lat, lon }]`.
