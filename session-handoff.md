## Живая проверка: как войти живым аккаунтом

SMS в разработке никуда не уходит — провайдер не подключён. Код входа лежит хешем в `otp_codes`
и подбирается тем же HMAC, каким считает сервер; готовый скрипт — `backend/scripts/dev-token.sh`:

```
./scripts/dev-token.sh +79170009009           # печатает accessToken
./scripts/dev-token.sh +79170007777 vendor.txt # и кладёт в файл
```

Требует локальной базы и `JWT_REFRESH_SECRET` из `.env`; на нелокальной базе и при
`NODE_ENV=production` отказывается работать. Refresh-токены ротируются: после 401 входить заново.

Аккаунты: пара `+79972874000` (свадьба `01a0795b-1199-7260-b7a7-f9c63e7de3a2`, 1 гость, 12 задач,
забронированная сделка с неверифицированным подрядчиком), пара `+79170009009`, подрядчик
`+79170007777` (верифицированная «Студия «Пион»», `01a07193-f775-7348-b035-32732263ce8a`),
посторонний `+79170001234`. Сквозной сценарий блока 10 оставил в базе свадьбу `E2E-464369`
(`01a07b3f-365d-75c4-9c49-76af759d4d24`) — по ней можно сверять строки без прогона.

Проверять обе стороны каждой функции (R-168) и три прохода на пункт: механически, чтением, живьём (R-132).

## Окружение

- **Кластер один** — служба `postgresql-x64-16` на 5432. Второй не поднимать (ERR-0132).
  Роль `tili` без `CREATEDB`, пароля `postgres` нет — миграции на пустой базе прогнать
  здесь нельзя (`RELEASE-BLOCKERS.md` №22).
- **Бэкенд** — `npm run dev` (127.0.0.1:3001), переменные из `backend/.env` (шаблон `.env.example`,
  в нём теперь и `CONTRIBUTIONS_MAX_PER_GUEST`, `COLD_OUTREACH_PER_DAY`). Фронт — 3000, `/api` в прокси.
  Для панели предпросмотра оба сервера описаны в `C:\Тили-тили\.claude\launch.json`
  (`tili-app`, `tili-backend`) — панель читает именно его, не `app/.claude/launch.json`.
- **Push на клиенте** читает `VITE_VAPID_PUBLIC_KEY` (`app/.env.example`); без ключа тумблер
  устройства честно выключен, `.env` под игнором.
- **База у тестов и dev-сервера общая** (R-177): сначала прогон, потом живая проверка; красное
  рядом с работающим сервером — повторить в одиночку. За день аудита в базе накопились тысячи
  дайджестов соседей — тесты, считающие «первые N из очереди», от этого зависят (ERR-0194).
- **psql на этой машине:** `PGPASSWORD=tili PGCLIENTENCODING=UTF8 "/c/Program Files/PostgreSQL/16/bin/psql.exe"
  -U tili -d tili -At -c "…" | tr -d '\000'`; кириллицу в `-c` не передавать.
- **Грабли инструментов** (все в `ERRORS.md`): `awk 'NR>=N'` в этом bash создаёт файлы с именем `N`
  — резать `sed -n`; heredoc с кириллицей ломается — тексты через инструмент записи и
  `git commit -F файл`; упоминание NUL как escape-последовательности инструмент правки
  превращает в байт (ERR-0186) — писать словом; в `vitest` `console.log` не ловится grep-ом и
  запрещён линтом — доказательства брать из `expect` и psql.
