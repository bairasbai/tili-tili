  GET возвращает карточки, пакеты и `free|held|busy|null`, PUT сериализует создание места/три позиции и атомарно заменяет по `replaceEntryId`, DELETE

- **019, фаза 3 / US1 frontend — MVP готов:** T015–T021. Блок места даёт список, удаление, отметки, exact-сравнение и двухшаговую
  замену брони: переход в анкету с `replaceSlot`, затем cancel + book выбранного пакета; обычный CTA при таком intent скрыт, а отказ после отмены назван явно. Анкета/выдача — добавление и явный chooser при лимите; `/compare` сверяет stable `entryId`, не подставляет других и для избранного требует ручные 2–3 галочки. Nullable-цена честно подписана,
  а старый deal-state `candidate` во всех UI/backend-текстах назван «Не связывались». Карты экранов/кнопок синхронизированы. Итоговое интеграционное ревью закрыло пять расхождений до коммита, включая один итоговый refresh составной замены и сохранение success/partial-error после нового снимка слота.
- **019, фаза 4 / backend:** T022–T025 готовы. Контракт 0.48.0 — 146 путей / 194 операции / 88 схем;
  строгие `OfferRequest`/`Offer`/`OfferPublic`, route-specific итоги batch-запроса, bare vendor array. Пара шлёт один–три
  запроса только кандидатам с partial success, snapshots и квотой 10/24 ч; кабинет видит только свои запросы и отвечает
  пакетом/custom/decline с квотой 5/24 ч и default сроком +7 в поясе свадьбы. Тихие уведомления не раскрывают чужие
  имена, цены и тексты. Неуспешный ответ больше не закрепляет idempotency-key (ERR-0325). Request row — единственный mutex
  версий; активный offer не блокируется до vendor/package, что убирает offer↔vendor deadlock при удалении пакета (ERR-0326).
  `offers019.test.ts` теперь содержит 16 DB-сценариев: исходные 14 плюс stale-409/default +7 и детерминированная гонка

## Окружение

Текущая сессия Codex: Node 24.19.0 и закреплённый проектом pnpm 10.34.5 через `corepack`; `psql`, `pg_isready`,
`redis-cli` и Docker отсутствуют. Поэтому тесты, которым нужны PostgreSQL/Redis, здесь можно проверить только
статически и отправить в удалённый CI; локально доступны типы, unit-тесты без сервисов, линт и сборка. Проект и CI
ожидают Node 22 — окончательный gate остаётся за CI/окружением с сервисами. Миграции 018-A и 018-B правились на
месте: базу, где накатана версия из архива, пересоздать.
