# Проверка изменений и независимое ревью

## Проверка поведения

- До проверки определи пользовательский сценарий и наблюдаемый результат. Для изменения поведения начни с быстрых адресных проверок, затем пройди затронутый сценарий через штатный UI, API или CLI в разрешённой среде. При сбое зафиксируй шаг, ожидаемый и фактический результат на текущей версии.
- Выбирай дополнительную проверку по риску. Для инвариантов, включая повтор операции, используй характерные и граничные входы или генератор, если он уже есть. При замене реализации сравни результаты на одинаковых входах и явно зафиксируй согласованные различия.
- Проверяй по согласованным требованиям и критериям из базовой версии. Если изменение затрагивает саму проверку, покажи отдельно, почему новые критерии соответствуют контракту и обнаруживают исходный риск. Для нового блокирующего правила оцени ложные срабатывания на известных успешных и проблемных случаях.

## Независимое ревью

- Для предусмотренного задачей ревью плана или спецификации передай проверяющему в свежем контексте согласованную цель, документ, ограничения и относящиеся к задаче исходники. Дай ему самому найти неявные предположения, пробелы и расхождения с кодом.
- Для ревью реализации передай текущий diff, критерии из согласованной базы и затронутые исходники. Проси указать конкретный риск, файл и сценарий воспроизведения. Последующие проверки опирай на подтверждённые замечания и изменившиеся участки. Полномочия на делегирование и проектные проверки действуют в полном объёме.
