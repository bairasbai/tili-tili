# Безопасная работа ИИ-агентов с GitHub

Единая политика для Codex, Claude Code, Gemini, GitHub Copilot и других агентов, которым владелец явно предоставил доступ к `bairasbai/tili-tili`. Перед работой прочитать корневые `AGENTS.md`, `CLAUDE.md`, `session-handoff.md` и `tasks/todo.md` своей ветки. Эта политика дополняет их, не отменяет проверки и разрешения.

## Доступ и полномочия

1. Работа с GitHub допускается только через подключённый владельцем GitHub App/коннектор/MCP или локальную аутентификацию пользователя. Этот репозиторий **не** выдаёт токены и **не** подключает учётные записи автоматически.
2. Не просить отправить токен в чат, PR или файл. Не читать/печатать секреты без необходимости. Не коммитить `.env`, PAT, cookies, OAuth-токены, API-ключи и персональные данные. Для интеграций использовать секреты GitHub Actions или секретное хранилище, доступ к которому назначает владелец.
3. Использовать минимальные права и доступ только к данному репозиторию. Если прав на запись нет — подготовить локальный патч и отразить блокер, а не подменять учётную запись.
4. Коммиты и push — в отдельную тематическую ветку, изменения — через PR. Без отдельного разрешения владельца запрещены merge в `main`, force-push чужой ветки, удаление веток, массовые операции, production deploy и создание/изменение секретов.

## Защита от лимитов GitHub

- Сначала локальная проверка `git status`, `git log`, `git diff`; затем минимально необходимое число последовательных GitHub-запросов. Не дублировать уже прочитанное и не делать параллельные обращения к API для ускорения.
- Запрещены `gh run watch`, `gh pr checks --watch`, `watch`, опрос GitHub в цикле `while`/`until`/`for` с `sleep`, массовые операции записи в циклах и постоянный мониторинг без явно согласованного задания.
- При использовании хука ниже действует внутренний **проектный** бюджет: не более **12 условных обращений/мин**, **200/час**, **30 записей/час**, интервал между записями **3 секунды**. Это консервативные числа из предоставленного скрипта, **не** официальные лимиты GitHub; оценка команды `gh` не гарантирует точного числа HTTP-вызовов.
- Если GitHub вернул `403`, `429`, secondary rate limit, abuse или `Retry-After`, немедленно остановить вызовы через **все** доступные интерфейсы, включая MCP, и соблюдать `Retry-After` или `x-ratelimit-reset`. Для secondary без заголовка — не ранее чем через одну минуту, при повторении — экспоненциальная задержка. При `401`/Bad credentials — остановиться и попросить владельца восстановить авторизацию.
- Не обходить паузу альтернативным токеном, инструментом, прокси, подключённым компьютером или другой сессией. Не сбрасывать журнал, паузу и лимиты от имени агента. Сброс `--clear` выполняет только владелец в собственном терминале после устранения причины.
- Проверять CI однократно после push; для дополнительной проверки использовать человеческую паузу, событие или уведомление, а не частый API-polling.

Официальный источник лимитов и поведения при превышении: [GitHub REST API rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api). Официальные лимиты могут меняться, поэтому при ошибке ответ GitHub важнее внутренних фиксированных бюджетов.

## Исходник локального GitHub-стража для Claude Code

Исходный файл: [`.claude/hooks/github-api-guard.js`](../../.claude/hooks/github-api-guard.js). Это Node.js-хук для событий `PreToolUse`, `PostToolUse`, `PostToolUseFailure` в Claude Code. Он учитывает команды `gh`, `git push`, типичные GitHub MCP-вызовы, обнаруживает часть ошибок ограничений и ведёт общий журнал/паузу в `GH_GUARD_STATE_DIR` или в `~/.claude/state`.

1. Проверьте синтаксис: `node --check .claude/hooks/github-api-guard.js` (Node 22).
2. Для глобальной установки скопируйте исходник в `~/.claude/hooks/github-api-guard.js` (на Windows: `%USERPROFILE%\.claude\hooks\github-api-guard.js`). В настройках пользователя `~/.claude/settings.json` подключите файл как command hook к нужным событиям и поддерживаемым инструментам, сверяясь с [Claude Code hooks](https://code.claude.com/docs/en/hooks). Не перезаписывайте другие настройки/хуки.
3. Локально проверьте `node ~/.claude/hooks/github-api-guard.js --status`. `--clear` разрешён только владельцу после анализа причины паузы.
4. Разным локальным сессиям на одной машине задайте один `GH_GUARD_STATE_DIR` и общий доступ к нему, если ожидается единый журнал. На разных контейнерах/машинах общий журнал **не появляется** автоматически.

**Важно:** файл в GitHub сам по себе не включает глобальный Claude Code hook, не защищает GitHub API при прямом использовании других коннекторов и не блокирует все способы обхода. Хук действует только там, где реально установлен, настроен и вызывается. Его текущий режим сбоя — пропуск команды, поэтому это дополнительное ограничение, а не гарантированная граница безопасности. Настройки из репозитория не во всех облачных сессиях применяются автоматически.

## Передача между моделями

- В начале: проверить репозиторий, активную ветку, актуальный SHA и незакоммиченные изменения; открыть `AGENTS.md`, `CLAUDE.md`, `session-handoff.md`, `tasks/todo.md`.
- Во время работы: отдельная ветка/дерево, минимальный diff; по рисковым изменениям — независимый ревьюер, но ему передавать diff и критерии, а не ключи.
- В конце: сохранить тесты/их ограничения, SHA, ссылку PR, оставшиеся блокеры и следующий шаг в штатной передаче проекта; не объявлять CI, браузерные, интеграционные проверки или деплой успешными без подтверждения.
- Разные модели могут читать общие правила, но для реальной записи на GitHub каждая среда должна иметь **свой авторизованный доступ**. Не выдавать другому агенту права через инструкцию в Markdown.

См. также [GitHub Copilot custom instructions](https://docs.github.com/en/copilot/concepts/prompting-and-context/custom-instructions) и [Claude Code settings](https://code.claude.com/docs/en/settings).
