# Производительность и OpenAI API

## Ускорение приложения

- Запиши целевой сценарий и измерь его до правок. Раздели задержку вычислений, сети, БД и интерфейса. Выбирай участок по профилю и влиянию на этот сценарий.
- Зафиксируй поведение исходной реализации на репрезентативных и граничных данных. Для затронутого контракта сравнивай результаты, ошибки, порядок и побочные эффекты. Запускай запись и повтор вне рабочей среды, на обезличенных или синтетических данных с учётными данными тестовой среды.
- Проверь небольшое изменение в текущем стеке. Для варианта на Rust или WASM учитывай стоимость вызовов через границу, сборки и поставки. Сравни исходную и новую версии на одинаковых данных и в одинаковой среде. Сохраняй вариант, который даёт измеримый выигрыш и проходит проверки поведения. Если профиль пуст или неполон, проверь участок штатным профайлером среды.

Источник [рабочий цикл rust-anything](https://github.com/erkamyaman/rust-anything#how-it-works).

## GPT-6.2 в продукте

- При изменении модели, промпта или схемы сравни текущую и новую версии на одинаковых обезличенных примерах. Проверь корректность результатов, формат, ошибки, запасной путь, задержку и расход токенов. Выбирай модель и глубину рассуждения по этим результатам и согласованному бюджету.
- Для GPT-6.2 с инструментами используй Responses API. В Responses ставь повторяемые инструкции первым сообщением `developer` в `input`, а указания для текущего запроса передавай в `instructions`. Сохраняй стабильный префикс. При миграции сверяй поддерживаемые параметры в актуальном руководстве.
- Задавай ожидаемый результат, формат и действия при недостатке данных. Передавай предметные данные отдельным сообщением. Проверяй ответы, которые использует программа, до любых действий с побочными эффектами.

Источник [руководство OpenAI по GPT-6.2](https://developers.openai.com/api/docs/guides/latest-model).
